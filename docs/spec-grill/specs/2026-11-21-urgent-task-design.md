## 概要

task-trail に、突発（その場か当日中に対応する）のタスクを、スケジュール画面から素早く登録する機能を足す。

**入力（依頼文の要約）**: 「緊急のタスクを対応するときの機能を追加したい。既存機能で対応できる場合は、追加対応は取り下げる」。質問で、対象を「その場もしくは当日中に対応する突発のタスク」に、困りごとを「素早く登録したい」に絞った。入力ファイルはない。

**既存機能で足りるかの判断（コードと `docs/development.md` を読んで確かめた。実ブラウザでの操作は未確認）**: 足りない。判定の基準は、「突発のタスクを、スケジュール画面だけで、件名の入力と確定の操作で、今日のタスクに載せられるか」。今の突発タスクは、追加（件名は「新しいタスク」、開始は今日、期限は 7 日後）→ 件名と期限の編集 → スケジュール画面で枠を置く、の 3 手で、枠を置くまで「今日のタスク」に載らない。基準を満たさない。

**見送った案**:
- 「突発対応」という普通のプロジェクトを 1 つ使う案。データ形式・表示・稼働を変えずに済み、変更が最小になる。ただし、利用者は、変更の大きさを説明されたうえで、タスクの「プロジェクトなし」を許す案を選んだ（Q7・Q22）。
- 緊急を示す専用の印・状態、点数の規則の変更。利用者が、印は付けないと決めた（Q2）。
- 緊急時に、他のタスクの日程を一括で動かす機能。困りごととして選ばれなかった（Q1）。

**作るもの**:
1. スケジュール画面の日表示で、空き時間を押すと、その場に入力欄が開く。件名・プロジェクト・長さを入れて確定すると、タスクの追加と作業枠の配置を 1 操作で行う。
2. タスクの「プロジェクトなし」（`projectId` が null）を、データ形式から許す。
3. プロジェクトなしのタスクの、表示・稼働・付け替え（プロジェクトなし → プロジェクト、プロジェクト → 別のプロジェクト、プロジェクト → プロジェクトなし、のどの向きでも）。

## 流れ

1. スケジュール画面を日表示にする（週表示では使えない）。
2. 日表示の空き時間のボタンを押す。空き時間は、既存と同じ（20 分以上の空きのボタン）。どの日の空き時間でも押せる。休みの日は、既存どおり空き時間が出ないので、押せない。
   - 選択中のタスクがあるときは、既存の動き（選択中のタスクの 60 分の枠を置く）のまま。選択中のタスクがないとき（既存では「先にタスクを選んでください」と出る場面）に、入力欄が開く。
   - 開始時刻は、押した空き時間のボタンの先頭を、既存の枠の配置と同じ刻みに丸めた時刻。
3. その場に開く入力欄に、件名を入れる。
   - プロジェクトの選択欄は、「プロジェクトなし」と既存のプロジェクト。既定は「プロジェクトなし」。
   - 長さは、15・30・45・60 分から選ぶ。初期値は 30 分。
   - 確定は Enter か確定のボタン（日本語入力の変換確定の Enter では確定しない）。Esc か、入力欄の外を押すと、何も作らずに閉じる。操作は、既存の会議の追加と同じ流れに合わせる。
4. 確定すると、タスクと枠を作る。件名が空のときは、確定できない。
   - 期限・開始日は、押した日。状態は `In Progress`。大項目・中項目・重要度・メモは空。
   - 枠は、開始時刻から、選んだ長さ。種別（予定・実績）は、既存の配置と同じ規則（過去の時刻は実績、未来は予定）。会議と重なるときは、警告を出して置く。別の枠と重なる・置けないときはエラーで、入力欄が残る（タスクも作られない）。
5. 枠が今日にあれば、「今日のタスク」に載る。今日以外の日に置いた枠は、その日になるまで載らない。

プロジェクトなしのタスクの扱い:
- ID は、固定の接頭辞 + 連番（例: `X1`）。連番は、全タスクの ID を見て、重ならない番号を使う。プロジェクトを選んだときは、既存の ID の採番（`プロジェクトID + 連番`）。
- ガントチャートとリストの末尾に、「プロジェクトなし」の区切りを出す。ほかのタスクと同じ編集・状態変更・バーのドラッグ（日程）ができる。区切りの中の並び替えは、できない。
- ガントチャートとリストのプロジェクトの絞り込みの選択肢に、「プロジェクトなし」を足す。
- 「今日の優先」に、ほかのタスクと同じ点数の規則で出す。プロジェクト名の欄は、「プロジェクトなし」と出す。
- プロジェクトの進捗率・期限超過・遅延の集計には含めない（プロジェクトに属さないため）。プロジェクトの種別・状態・マイルストーン・削除のように、プロジェクトを前提にした機能は、プロジェクトなしのタスクには働かない（対象外）。
- 稼働の画面では、「プロジェクト未設定の会議」の行を、「プロジェクト未設定」に改め、タスク列に実績の枠の時間、会議列に会議の時間を出す。
- 前のタスクは、プロジェクトなしのタスクに付けられない。
- 編集の窓の選択欄で、プロジェクトを付け替えられる。
  - 自分の `predecessors` が空でなく、または他のタスクの前のタスクに指されているタスクは、付け替えられない（理由を表示する。利用者が先に外す）。
  - 付け替えても、ID は変えない。大項目・中項目は空にして、付け替え先の最後に入れる。
- 依頼（inbox）の `addTask`・`moveDue` と WBS の取り込みは、プロジェクトなしに対応しない。プロジェクトなしのタスクがあるデータで、依頼や取り込みを実行しても、エラーで止まらず、そのタスクは対象外になる。

## 受入条件

- 選択中のタスクがない状態で、日表示のどの日の空き時間を押しても、入力欄が開く。件名だけ入れて確定すると、既定値（プロジェクトなし・30 分）で、タスクが追加され、開始時刻から 30 分の枠が置かれる。確定するまでに、別の画面へ移らない。
- 選択中のタスクがあるときは、既存の動き（60 分の枠を置く）のまま。
- 入力欄は、Esc か外を押すと、タスクも枠も作らずに閉じる。日本語入力の変換確定の Enter では確定しない。件名が空のときは確定できない。週表示では開かない。
- 枠が今日にあれば、「今日のタスク」と「今日の優先」に載る。今日以外の日の枠は、その日になるまで「今日のタスク」に載らない。
- 追加されたタスクは、期限・開始日が押した日、状態が `In Progress`。選択欄から、既存のプロジェクトも選べる。
- 枠が会議と重なるときは、警告を出して置く。別の枠と重なる・置けないときはエラーで、入力欄が残る（タスクも作られない）。
- プロジェクトなしのタスクの ID は、既存の ID と重ならない（付け替えで、`X` の ID が各プロジェクトに残っても、重ならない）。
- プロジェクトなしのタスクが、ガントチャートとリストの末尾の区切りに出て、編集・状態変更・日程のバーのドラッグができる。区切りの中の並び替えはできない。前のタスクは付けられない。絞り込みの選択肢に「プロジェクトなし」がある。
- プロジェクトの進捗率・期限超過・遅延の数に、プロジェクトなしのタスクが入らない。
- 稼働の画面に、「プロジェクト未設定」の行がある（行名が「プロジェクト未設定の会議」ではない）。その行のタスク列に、プロジェクトなしのタスクの実績の枠の時間が出る（例: 過去の時刻に置いた 30 分の枠のタスク 1 件で、30 分増える。予定の枠は数えない）。会議列は、今までどおり。
- 編集の窓で、プロジェクトを付け替えられる（どの向きでも）。前のタスクまたは次のタスクがあるタスクを付け替えようとすると、理由が出て、付け替わらない。付け替え後も ID は同じで、大項目・中項目は空、付け替え先の最後に入る。
- `data.json` にプロジェクトなしのタスク（`projectId` が null）があっても、検証（`schema.js`）が通り、保存できる。`sample.json` に、プロジェクトなしのタスクの例を入れる。
- その `sample.json` で、ガントチャート・リスト・スケジュール・稼働・設定・「今日のタスク」・「今日の優先」を開いても、例外が出ない。依頼（inbox）と取り込み（intake）を実行しても、エラーで止まらない。
- 追加するテスト: 検証（`projectId` が null）、枠の配置（登録）、稼働の集計、付け替え（許可と拒否）、ID の採番、今日の優先。`npm test` が通る。
- `docs/development.md` の該当の節と、`docs/flow.html` の変えた分岐を直す（確かめていない箇所は「未確認」と書く）。`npm run build` で `assets/task-trail.html` を更新して、コミットする。

## 非目標

- 緊急を示す専用の印・状態・点数の規則の変更（利用者が、印は付けないと決めた）。
- 緊急時に、他のタスクの日程を一括で動かす機能。
- 週表示からの登録。
- 依頼（inbox）の `addTask`・`moveDue` と WBS の取り込みを、プロジェクトなしに対応させること（`addTask` と WBS は、利用者が、対応しないと決めた）。
- プロジェクトなしのタスクの並び替えと、前のタスクの設定（利用者が、並び替えは不要と決め、前のタスクは選ばなかった）。
- プロジェクトなしのタスクが入った `data.json` を、古い版の task-trail で開けるようにすること。

## リスク

- プロジェクトなしのタスクを許すと、`projectId` を使う約 150 か所（`src/` 全体: `core/impact.js`・`core/metrics.js`・`core/workload.js`・`ui/edit.js`・`views/` など）の前提が崩れる。直し忘れが、画面の表示崩れや例外になるおそれがある。実装の計画で、使用箇所を、「対応する／対象外にする／例外にならないだけ」に仕分ける。
- 付け替えても ID を変えないため、付け替えたタスクの ID の接頭辞（`X`）と、所属するプロジェクトが食い違う。ID が変わらないので、予定枠・変更履歴・依頼の参照は切れない（未確認）。
- 今日以外の日に登録したタスクは、状態が `In Progress` のまま、期限がその日になる。今日のタスクに載らない。
- プロジェクトなしのタスクが入った `data.json` を、古い版の task-trail で開くと、検証で止まる。
- 日表示の空き時間を押す操作が、既存のドラッグ・選択と競合するおそれがある。実ブラウザ（Playwright）での確認が要る。タッチ操作と日本語入力（IME）は、未確認のままになる。
