## 概要

project-lens（`D:\claude\local-repo\project-lens`）に、複数人で使うためのデータ分割・突発タスクと編集の拡張・ID の見直し・履歴の整理・「重要」の印を、まとめて加える。互換性は考慮せず、旧形式のデータの移行は作らない。

### 入力
依頼文（11 項目）:
1. 複数人でスケジュール管理する際に備えて、data.json からスケジュールや稼働を分けたい。
2. 突発タスクの追加を、週のスケジュールからもできるようにしたい。
3. 突発タスクの追加ボタンが右上にほしい。
4. タスクの編集を、スケジュールからでもできるようにしたい。
5. タスクを別プロジェクトに移動できるようにしたい。
6. タスク ID はアルファベットだが、Z を超えても問題にならないか確認し、必要なら直したい。
7. 日程変更の履歴は必要か。見直すことはなく、データが重くなる原因になりそう。
8. 重要度ではなく「重要」にし、チェックボックスで有効・無効を切り替えられるようにする。
9. 重要なタスクは、リストでも、ガントチャートと同じく色を付ける。
10. 重要なタスクは、今日のタスク・今日の優先でも、色かマーカーを付ける。
11. 重要なタスクは、スケジュールでも、色かマーカーを付ける。

参考資料の指定はない。リポジトリの `docs/development.md`・`core/schema.js`・`ui/edit.js`・`ui/views/*.js`・`ui/app.js` を読んで、現状を確かめた（調べて分かった現状: 5 は、ガントの編集の窓の「プロジェクト」の選択欄で、すでに付け替えられる。6 は、プロジェクト ID が A〜Z の次に `P1`・`P2` になり、タスク ID が「プロジェクト ID + 連番」なので、`P1` の 11 番と `P11` の 1 番が同じ `P111` になって衝突する。プロジェクト `X` は、プロジェクトなしのタスクの接頭辞 `X` と衝突する）。

## 流れ

### データの分割（依頼 1）
- 共有ファイル（`data.json`）に、プロジェクト・タスク・変更履歴（`changeLog`）と、共有の設定（`countWeekendsAndHolidays`・`nationalHolidays`・`waitingLongDays`・`projectRules`・`labels`・`wbsMappings`・`wbsImports`）を置く。
- 個人ファイル（既定は `<保存先>/personal.json`）に、作業枠（`sessions`）・会議（`events`）・個人の設定（`workday`・`holidays`・`workdays`・`selfEmails`・`selfNames`）・依頼（`inbox`）を置く。
- 個人ファイルの形は、直下に `sessions`・`events`・`settings`（個人の設定）・`inbox` を持つ。作業枠は、`taskId` を持つ平らな配列で、枠の ID は個人ファイルの中で重複しないようにする。個人ファイル用の検証と、同梱の個人用のサンプルを足す。
- 画面は、共有ファイルと個人ファイルを別々に選んで開く。どちらかが揃うまで画面を開かず、足りないファイルを選ぶよう案内する。前回の 2 つは記憶して、自動で開く（片方が失われたときも、足りない方を案内する）。
- CLI は、`--data`（保存先のフォルダ）に加えて、`--mine <ファイル>` で個人ファイルを指せる。省略したときは `<保存先>/personal.json` を使う。各ツールは、必要なファイルを `--data`・`--mine` から読む。依頼（`inbox`）・予定表の取り込み（`calendar-*`）は個人ファイル、Excel の取り込み（`wbs-apply`）・祝日の取得は共有ファイルを書く。両方に触れる操作は、両方のファイルを書く。`init` は、同じ保存先に両方のファイルを作る。
- 保存・競合の検知・当て直し・自動の読み直しは、ファイルごとに独立して行う（読み込み時刻をファイルごとに持つ）。1 回の操作で 2 つのファイルを書くとき、片方が失敗したら通知する。
- 共有ファイルは、SharePoint Online 上のファイルを、ネットワークドライブとして割り当てた（または同期した）フォルダ経由で開く想定にする。個人ファイルは、各自の手元に置く。画面の自動の読み直し（帯が開いている間や依頼の処理中は 4 秒、そうでなければ 16 秒ごと）は、共有・個人の両方のファイルに行う。https の URL での直接の読み書きは作らない。
- 読むのは自分の個人ファイルだけにする。他の人の稼働の表示と、タスクの担当者の項目は作らない。
- 稼働・今日のタスク・空き時間は、個人ファイルの作業枠と会議から計算する。
- 共有ファイルのタスクが消える・別のプロジェクトへ移るとき、個人ファイルの作業枠は、タスク ID で結びつくので、そのまま残る（ID は変わらない）。共有ファイルに無いタスクの作業枠（対応するタスクが無い作業枠）は、検証が注意（warning）にする。
- 共有ファイルと個人ファイルが食い違うのは、「共有ファイルに無いタスクの作業枠が、個人ファイルにある」ときだけ（逆の、作業枠の無いタスクは、食い違いではない）。このとき、画面上部のバナーに「共有ファイルに無いタスクの作業枠が N 件あります」と出し、その作業枠はカレンダーに出さず、データも消さない。読み直しのたびに確認し、一時的なずれは、次の読み直しで、注意ごと消える。
- バナーに「該当の枠を削除」ボタンを付ける。押すと、確認の文（「N 件の作業枠を削除します。タスクが戻っていないか、少し待ってから確認してください」）を出し、承認されたら、個人ファイルから該当の作業枠だけを消す。

### タスク ID（依頼 6）
- プロジェクト ID は、英字 2 文字（`AA`〜`ZZ`）にする。`ZZ` は、プロジェクトなしのタスク用に予約するので、プロジェクトは 675 個（`AA`〜`ZY`）まで作れる。
- タスク ID は、`<プロジェクト ID>-<4 桁>`（`AA-0001`〜`AA-9999`）にする。プロジェクトなしのタスクは `ZZ-0001` から。
- 上限（プロジェクト 675 個・1 プロジェクトの番号が 9999 を超えるとき）は、追加を止めて、エラーで知らせる。
- 採番は、「いまのタスクと、残る履歴の ID の、最大の番号 + 1」のままにする（番号をデータに持たない）。
- ガント・リストの ID は、常に表示する（隠すボタンは作らない）。ID が長くなる分、ガントのラベルとリストの ID 列の幅を広げる。

### 履歴（依頼 7）
- 画面での期限変更の記録（`source: "screen"`）と、原因を選ぶ欄（`setLogCause`）を廃止する。
- 依頼（inbox）・Excel 取り込み・予定表の取り込みが書く履歴は残す。プロジェクト画面の履歴の表示は、これらだけに使う。依頼・取り込みの履歴は、件数の上限や古い記録の削除を設けない（1 回の依頼・取り込みにつき 1 件で、画面の操作のように、動かすたびには増えない）。

### 重要（依頼 8〜11）
- 「重要度」を「重要」にする。データは `important: true`（重要でないときは項目を持たない）にし、画面は、編集の窓とリストの列のチェックボックスで切り替える。ガントの印・検証・今日の優先の点数・定例タスクの引き継ぎも、`important` を使う形に直す。
- 今日の優先の点数の「重要 +12」は、据え置く。`important` が無い・`false` のときは足さない。
- リスト: ガントと同じ印（行の左端の赤い太線と、薄い赤の背景）を付ける。
- 今日の優先: 行の理由の「重要度: 高」の文字があった位置に、赤い「重要」バッジを付ける。
- 今日のタスク: 件名の右、状態の pill の隣（行の一番右）に、同じバッジを付ける。
- スケジュール: 作業枠の中の件名を赤字・太字にし、枠の左端に赤い線を付ける（週表示・日表示の両方）。枠の色（予定・実績・未確認）は変えない。バッジは付けない。週表示の「期限」の行の件名も、赤字・太字にする。
- 完了（`Done`・`Cancelled`）したタスクには、どの画面でも印を付けない。
- Excel（WBS）取り込みの `importance` の列は、廃止する（取り込まない）。取り込み後の重要は、画面で付ける。
- 旧形式の `importance` は読まない（無視する）。依頼（inbox）の保存済みの操作名 `setImportance` は、残す。

### 突発タスクの追加（依頼 2・3）
- ヘッダーの右上に、「突発タスク」ボタンを置く（どの画面でも出る）。
- ボタンを押すと、スケジュール画面へ移ってから、入力欄を開く。入力欄は、件名・プロジェクト・長さ（15・30・45・60 分）に、日付と開始時刻を足した形にする。
- 日付の初期値は、スケジュール画面で選んでいる日（ほかの画面からは今日）にする。開始時刻の初期値は、その日の勤務時間内で、会議・作業枠と重ならない、いまから最初の空き時間の開始（空きが無いときは、勤務の開始時刻）にする。
- 週表示でも日表示でも、同じボタン・同じ入力欄で追加できる。日表示の空き時間を押す方法は、今までどおり残す。週表示に、空き時間を押す方法は足さない。
- 確定の規則（Enter・日本語入力の変換確定・枠を置けないときのエラー・「今日のタスク」への載り方）は、今のままにする。

### タスクの編集とプロジェクトの移動（依頼 4・5）
- スケジュール画面で作業枠を選ぶと、選択中の操作の行に「タスクを編集」ボタンが出る。押すと、カレンダーの上（会議の編集欄と同じ場所）に、タスクの編集欄が開く。
- 編集欄には、よく使う項目（件名・期限・開始・状態・重要・プロジェクト・メモ）を出し、「詳細を開く」で、ガントの編集の窓と同じ項目（繰り返し・チェックリスト・前のタスク・複製・削除など）をすべて出す。
- プロジェクトの付け替えは、ガントの編集の窓（すでにある）とスケジュールの編集欄に加えて、リストの各行にも「プロジェクト」の選択欄を足して行えるようにする。前のタスク・次のタスクがあるタスクは、今までどおり、付け替えず、「先に外してください」と出す。

## 受入条件
1. 画面を開くには、共有ファイルと個人ファイルの 2 つを選ぶ。どちらかが無いと、画面は開かず、足りないファイルを選ぶ案内が出る。前回の 2 つを記憶して自動で開く。
2. 作業枠・会議・勤務時間・休み・営業日として扱う日・自分の特定（`selfEmails`・`selfNames`）・依頼は個人ファイルに保存され、共有の `data.json` には書かれない。プロジェクト・タスク・履歴・共有の設定は共有ファイルに保存される。
3. CLI は `--mine` の指定を受け、省略すると `<保存先>/personal.json` を使う。`init` は、両方のファイルを同じ保存先に作る。
4. プロジェクトを 675 個まで作れて（675 個目は `ZY`）、`XX` を含めて、ID が重複しない。`ZZ` はプロジェクトに割り振られない。
5. タスク ID が `AA-0001` の形で採番され、プロジェクトなしは `ZZ-0001` から。プロジェクトの 676 個目と、番号が 9999 を超えるタスクの追加は、エラーで止まる。
6. 画面で期限を動かしても、`changeLog` に記録が増えない。依頼・Excel 取り込み・予定表の取り込みの記録は、今までどおり残り、プロジェクト画面の履歴に出る。
7. 「重要」のチェックボックスで、`important: true` を付け外しできる。今日の優先の点数は、`important: true` のときだけ +12 になる。
8. 重要で未完了のタスクに、リスト（左端の赤い太線・薄い赤の背景）・今日の優先（理由の位置の赤い「重要」バッジ）・今日のタスク（件名の右、状態の pill の隣のバッジ）・スケジュール（週表示・日表示の枠の赤字・太字と左端の赤い線、週表示の期限の行の件名の赤字・太字）で、決めた印が出る。`Done`・`Cancelled` のタスクには出ない。
9. スケジュール以外のすべての画面（ガント・リスト・稼働・設定）で、ヘッダー右上のボタンを押すと、スケジュール画面へ移って入力欄が開く。入力欄の初期値は、選んでいる日（なければ今日）と、いまから最初の空き時間。週表示でも追加できる。日付・開始時刻を指定して追加でき、枠を置けないときは、タスクを作らず、エラーを出して欄を残す。
10. スケジュールで枠を選んで「タスクを編集」を押すと、カレンダーの上に編集欄が出て、変更がタスクに保存される。「詳細を開く」で、全項目が出る。
11. リストの「プロジェクト」の選択欄で、タスクを別のプロジェクト・プロジェクトなしへ移せる。前後のタスクがあるときは、移せず、選択欄が元に戻る。
12. `npm test` が通り、`npm run build` で `assets/project-lens.html` を作り直してコミットする。`importance`・`setLogCause` が、`docs/development.md` と `src/` に残っていない（`grep` が 0 件。依頼の保存済みの操作名 `setImportance` と、旧データの扱いの説明を除く）。`docs/development.md` の対応する節・`docs/flow.html`・README・利用ガイドを、同じ作業の中で直し、PR の本文に「`development.md`: 直した節の名前」を書く。

13. 個人ファイルに、共有ファイルに無いタスクの作業枠があると、バナーに「共有ファイルに無いタスクの作業枠が N 件あります」と出て、その枠はカレンダーに出ない。共有ファイルにタスクが戻れば（読み直しのあと）、バナーが消え、枠が出る。「該当の枠を削除」を、確認で承認すると、その枠だけが個人ファイルから消える。

## 非目標
- 旧形式のデータ（`A`・`A1` 形式の ID、`importance`、1 ファイルの `data.json`）の移行・読み替え。旧形式のファイルは、手で直す（利用者の判断）。同梱の `sample.json`・既存のテストは、新しい形式に書き直す。
- 他の人の稼働・個人ファイルの表示、タスクの担当者の項目（利用者の判断。必要になってから足す）。
- ID を隠すボタン（利用者の判断）。
- 前のタスク・次のタスクがあるタスクの付け替え（今までどおり、先に外す）。
- 共有ファイルだけで開く動き（個人ファイルが無いとき。利用者の判断）。
- 2 つのファイルを、まとめて書く・競合を確かめる仕組み（利用者の判断。ファイルごとに独立して保存する）。
- https の URL での直接の読み書き（Microsoft Graph など。利用者の判断）。
- 「Claude Code に依頼する」から、重要の付け外しをすること（依頼の操作は `addTask` と `moveDue` に絞ったまま）。
- Excel（WBS）取り込みでの重要の指定（利用者の判断）。

## リスク
- 共有ファイルと個人ファイルは、別々に保存する。1 回の操作（たとえば、タスクを `Done` にして、未来の予定枠を解除する）で 2 つを書くとき、片方だけ成功すると、食い違う（作業枠が、状態の違うタスクを指す）。検証は、存在しないタスク ID の作業枠を、注意（warning）にして、保存は止めない。
- 採番は「最大の番号 + 1」なので、複数人が別々に共有ファイルへタスクを追加すると、同じ ID になりうる。検証が、ID の重複をエラーにする（保存できず、読み直して追加し直す）。
- 日付の計算（営業日で期限を置く提案など）は、個人の休み・勤務時間を使うので、人によって計算が食い違いうる。
- 履歴（依頼・取り込み）は、件数の上限を持たないので、使い続けると増える（画面の記録を止めるので、増え方は小さくなる）。
- 画面の保存・競合・読み直し（`ui/store.js`・`ui/sync.js`）と、CLI の保存（`tools/cli.js`）、見張り（`watch`）・`inbox`・`intake`・`intake-calendar` の手順は、1 ファイルを前提にした作りなので、2 ファイルに広げる変更が要る。
- SharePoint Online 上のファイルを、ネットワークドライブ・同期フォルダ経由で開いて保存できるか、自動の読み直しが遅くならないかは、実機で確かめていない（未確認）。
- ブラウザで 2 つのファイルを選んで開く動き（保存の権限・前回の記憶・自動の読み直し・競合の検知）は、実機で確かめていない（未確認）。
- 赤字・太字の件名が、予定（青緑）・実績（緑）・未確認（橙）の背景の上で、読みやすいかは、未確認。
- ID が `AA-0001` と長くなるので、ガントのラベル・リストの列の幅が増える。狭い画面での見え方は、未確認。
- 旧形式のデータは読み込めない（重要度の `importance` は読まれず、重要の印が出ない。旧形式の ID の `A`・`A1` は、新しい採番の規則に合わない）。
