# 算出の規則

優先順位・日程変更・状態と進捗の計算。[開発者向けの情報](../development.md)の一部。

## 優先順位（右の列と ToDo の候補の並び順）

対象は `Done`／`Cancelled` 以外のすべて（前のタスクが未完了のものも含む）。点数の合計が高い順（実装は `core/schedule.js` の `rankTasks`）。前のタスクのうち、データにあって完了していない（`Done`／`Cancelled` 以外の）ものが 1 つでもあれば、行の理由の先頭に「前のタスク待ち」を出す（`Waiting` の催促・確認の文言より前）。前のタスク待ちかどうかで、点数は変えない。データに無い ID の前のタスクは、待ちに数えない。

| 項目 | 点数 |
|---|---|
| 期限超過 | +100 |
| 期限点 | 残り 30 日以内は `(30 − 残り日数) × 1.5`（超過した分も加算）。残り 31 日以上は 0 |
| チェックリストの倍率 | 期限点に `1 + min(未チェックの項目数, 10) ÷ 10` をかける（最大 2.0）。`Waiting` は 1（かけない）。`+100` と重要にはかけない |
| 重要 | `important: true` なら +12 ／ それ以外 0（倍率のあとに足す） |
| 回答予定日の超過 | `Waiting` で `waitingOn.expected` が今日より前なら +40（倍率をかけない）。理由に「回答予定日を過ぎています（N日）」を出し、行の文言は「催促」にする |

- 例（重要でない）: 期限 5 日後・未チェック 3 件 ＝ 25×1.5×1.3 ＝ 48.75。期限 5 日後・項目なし ＝ 37.5。3 日超過・未チェック 10 件 ＝ 100＋49.5×2.0 ＝ 199。`Waiting`・期限 5 日後・未チェック 3 件 ＝ 37.5。期限 35 日後 ＝ 0。
- **Waiting の催促の対象**（`chaseTasks`。ToDo タブの「催促」。点数には足さない）: 状態が `Waiting` で、次のどちらか。
  - 回答予定日（`waitingOn.expected`）が、今日より前（厳密に `<`。今日の日付なら入れない）。
  - 回答予定日が無く、待ち始め（`waitingOn.since`）から今日までが `settings.waitingLongDays`（既定 7）日以上。待ち始めも無いときは入れない。
  - 回答予定日が今日以降なら、待ち始めが長くても入れない。日付の形でない `expected`・`since` は、無いものとして扱う。
  - 並び: 予定日を過ぎた日数が多い順 → 予定日の無いもので待った日数が多い順。同点は ID の順。
- 「このタスクを前のタスクとする未完了タスク 1 件ごと +10」と「`Waiting` +15」は、点数に含めない（設計判断を参照）。行の「理由」には、点数に使わなくなったあとも、「次のタスク N 件を止めている」と `Waiting` の催促・確認の文言を残す（`action: "chase"` も同じ）。点数は画面に出さない。
- 開始日（`start`）は参照しない。開始日の前でも載り、点数は 0 になりうる。
- 行の理由の「期限まで N日」は、期限点の範囲に合わせて、残り 30 日以内に出す。
- プロジェクトなしのタスクも、同じ点数で載る。行のプロジェクト名は「プロジェクトなし」と出す。
- 同点は期限の早い順、次に ID 順。丸めはしない。
- 右の列の「この週のタスク候補」（`views/prio.js` の `renderPrio`。ガントチャート・リスト・スケジュール画面）: 見る週は、今日のある週に固定する（週の移動は ToDo タブだけ）。出すのは、`weekTasks` の未完了の組（期限超過・今週に予定あり・今週の期限。「完了」の組は出さない）で、並びは `rankTasks` の点数の順（上の表）。件数の上限は設けない。今日のタスクに入っているタスクは、順位の計算は変えず、表示だけ除く。今週の候補に当たらないタスク（期限が来週以降で、今週に予定の枠も無い）は、点数があっても出さない。行には、理由（`rankTasks` の `reasons`）・「前のタスク待ち」・「今日へ」（スケジュール画面では出さず、ドラッグで置く）を出す。
- 遅れの表示（右の列の「今日のタスク」と「この週のタスク候補」、ToDo の左右の行。`views/prio.js` の `lateBadgesHtml`・`dueLateHtml`・`restReasons`）: 期限を過ぎた行に、白抜きの札「期限超過 N日」を、Waiting で回答予定日を過ぎた行に「回答予定を N 日超過」を、件名・状態の札の後ろに出す。行の左に赤の太い帯と薄い赤の背景（`li.late`）を付け、期限の日付は赤の太字で「期限 M/D（N 日超過）」とする。札にした 2 つの理由（「期限超過 N日」「回答予定日を過ぎています（N日）」）は、理由の文章からは除く（`restReasons`）。点数・並び順は変えない。完了したタスクには出さない。ガントチャートは、期限の日付に「▲ N 日超過」を赤の太字で添える（期限超過の行だけ。待ち先の文字は、その分右へずらす）。リストは、期限の欄に「▲ N 日超過」、待ち先・回答予定日の欄に「回答予定を N 日超過」を赤の太字で添える。ガント・リストの行は、遅れ（期限超過・回答予定日の超過）の未完了のタスクに、ガントはラベルの左に赤の帯（`.g-label.late-lab`）、リストは行頭に赤の帯（`tr.late`）と、行の薄い赤の背景を付ける。「重要」（紫の帯・背景）と重なる行は、紫の帯の内側に赤の帯を並べ、背景は赤を優先する。スケジュール画面の枠には出さない。確認したこと: ガントチャートとスケジュールで、見出し・取っ手の名前が「この週のタスク候補」になり、今日のタスクの下に、今週の未完了の 4 件が優先順に並ぶこと（Chromium・Playwright、デモデータ）。未確認: 暗い配色、幅 900px・700px、スケジュールでのドラッグ（`npm test` のみ）。

## 日程変更

- 前のタスク（`predecessors`）をたどり、次のタスクを**最小限だけ**動かす。前のタスクの新しい期限を超えないようにするだけで、余裕のある次のタスクは動かない。
- `Done`／`Cancelled` は動かさない。依存が入力されていないタスクも動かない。
- 前倒しのときは、「詰める」を選ぶと、次のタスクも同じ日数だけ前倒しする（前のタスクの新しい期限より前にはしない）。
- この計算（`core/impact.js`）を使うのは、「Claude Code に依頼する」の反映だけ。画面の期限の変更は、前後を見ずにそのタスクだけを保存する（「ガントチャートとリスト」（`ui-gantt-list.md`）の節）。

## 状態と進捗

- タスクの状態は `To Do`／`In Progress`／`Waiting`（待ち先を持つ）／`Done`／`Cancelled`（進捗率の分母から除く）。
- プロジェクトの状態は `計画中`／`進行中`／`保留`／`完了`／`中止`。
- 遅延・リスクは状態ではなく自動判定のバッジ。「期限超過 N件」、「待ち長期化」（`Waiting` が `settings.waitingLongDays` 日以上）、「プロジェクト期限超過」。
- 進捗率は `Done` ÷（`Cancelled` を除く全タスク）。
- `Waiting` の `waitingOn` は `{ party, since, expected? }`。`expected` は任意の回答予定日で、`Waiting` を外すと `waitingOn` ごと消える。回答予定日の欄は、ほかの日付の欄と同じ文字の欄（「画面の動き > 全体」（`ui-gantt-list.md`）の日付の欄）で、空にして確定すると予定日を外す。
- 定例タスク（`task.repeat`）は `{ unit: "week" }` か `{ unit: "month", day }`。`Done` にしたとき（画面の `setStatus`）、`spawnNextRepeat` が次回を 1 件作る。次の期限は、周期の日付のうち、旧期限と今日のどちらよりも後の最初の日（`core/repeat.js` の `nextRepeatDue`。毎月は短い月で月末に丸める）。件名・大項目・中項目・重要・メモ・繰り返し・チェックリスト（未チェックに戻す）を引き継ぎ、前のタスク・待ち先・作業枠・開始日は引き継がない。元の `repeat.spawned` に次回の ID を記録し、`Done` を戻して再度 `Done` にしても二重に作らない。`Cancelled` では作らない。タスクの複製（コピーを作る操作）は持たない（複製は不要と決めたため。使い回したい定例の作業は、繰り返しで次回が作られる）。
- 未確認（実ブラウザでの操作）: リストの回答予定日の欄、編集の窓の「繰り返し」、定例タスクの完了での次回の作成。ここまでの確認は、単体テストと、画面を開いたときにコンソールのエラーが出ないことだけ。
- チェックリスト（`task.checklist = [{ id, text, done }]`）は、タスクの状態と連動しない。全項目をチェックしても状態は変わらず、進捗率にも使わない。状態を `Done` にするときだけ、未チェックの項目があれば警告する（「ガントチャートとリスト」（`ui-gantt-list.md`）の節）。
- タスクの `projectId` は、`null`（プロジェクトなし）でもよい（`core/schema.js` の検証は、`null` か存在するプロジェクトの ID を受ける）。プロジェクトなしのタスクの ID は `ZZ-` + 4 桁の連番（`ZZ-0001`）。プロジェクトの ID は `AA`〜`ZY`（`nextProjectId`。使い切ったら Error。最大 675 個）で、`ZZ` は付けない。ID の形は検証しない（手で書いた `A1` のような ID もそのまま使える）。進捗率・稼働時間は、プロジェクト単位の集計なので、プロジェクトなしは含まない（稼働は「プロジェクト未設定」の行に出る）。
