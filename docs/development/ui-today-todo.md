# 画面の動き: 今日のタスク・ToDo・会議

今日のタスクとスケジュール、ToDo タブ、会議と稼働。[開発者向けの情報](../development.md)の一部。

## 今日のタスクとスケジュール

- スケジュール画面には、タスクの ID（`AA-0005` など）を出さず、件名だけで表す（利用者の判断）。対象は、日表示・週表示の枠、週表示の「期限」の行、「…の枠を削除」のボタン、編集欄の見出し（日付の範囲だけ）と「前のタスク」（`predEditHtml` の `{ ids: false }` で、札と選択肢を件名にする）、右の列（今日のタスク・この週のタスク候補）と、その行に出る予定枠の確認（`doneAskHtml` は「このタスクの未来の予定の枠…」。リストの行にも同じ文が出る）。スケジュールからも出る通知（実績の保存・状態の変更・Waiting・タスクの削除・定例の次回）も件名で言う（`app.js` の `taskTitle`。ほかの画面から出しても同じ文）。ガントのラベル・ガントの窓の見出し・リストの ID の列は ID を出したまま。`data-id`・`data-dragtask` などの属性と `aria-label` の ID は、表示ではないので残す。ガント・リストからだけ出る通知（タスクの追加の「AA-0008 を追加しました」など）は変えていない。存在しないタスクの Error（「タスク … がありません」）は ID のまま。
- 「この週のタスク候補」と「今日のタスク」の行には、チェックリストのあるタスクに細い線と「M/N（残り K 件）」を出す（今日のタスクの完了済み・取り消し済みの行には出さない）。
- 「今日のタスク」は、`views/prio.js` の `renderTodayTasks` が、今日の日付に作業枠があるタスクを枠から導く（保存しない）。ガントチャート・リスト・スケジュール画面の右の列（`renderSide`。`showPrio` に従う）で、「この週のタスク候補」の上に出る。
  - 行に状態の pill と、今日の枠の時間を並べる。時間の前に、枠の種類の札（`.ktag`）を付ける: 「予定」（青緑）・「実績」（緑）・「未確認」（橙の点線。過ぎた予定で、重なる実績の区間が無いもの。カレンダーと同じ `sessionKind(枠, now, actualSlots)`。時刻は右の列に渡す `now`）。色はカレンダーの凡例と同じで、文字も必ず出す。行に、実績を入れるボタンは付けない（実績は、スケジュール画面で入れる）。
    - 実績の入れ方: スケジュール画面で、始まった（開始が今以前の）予定の枠か、すでに `actual` を持つ予定の枠を選ぶと、実績の入力欄（`views/schedule.js` の `actualForm`。`.actform`）が出る。欄の形は、会議の実績の欄と同じ部品（`actualBox`）で、編集の領域（`#mtgslot`）の先頭に出す（「実績の欄（予定の枠と会議で共通）」）。日付・開始・終了の初期値は、その枠の `actual` があればそれ、なければ予定の日付・時刻。直して「実績を保存」（`data-actsave`。`actual` があれば文言は「実績を更新」）を押すと、`edit.js` の `recordSlotActual` が、`core/sessions.js` の `setActual` でその枠の `actual` を書く（あれば上書き）。タスクが To Do・Waiting なら In Progress にする（`updateTask`。Waiting の待ち先は外れる。Done・Cancelled は変えない）。枠と状態は 1 回の保存（`apply` 1 回）で変える。「実績を消す」（`data-actclear`。`actual` があるときだけ）は、`clearActual` で `actual` だけを外し、予定の枠は残す（状態は戻さない）。ほかの実績の区間（実績だけの枠を含む）と重なるとき・開始が今より後のときは、何も変えずにエラーの通知。休みの日には置ける。会議との重なりは警告だけ。`actual` を持つ予定の枠は、重なる実績が無くても未確認でなくなる。
    - ヘッダーの「＋ 実績を追加」（`data-actadd`。どの画面からも押せる）は、タスク（Done・Cancelled 以外。選択肢にプロジェクト名を添える）・日付・開始・終了の入力欄を開く。日付の初期値は、スケジュール画面なら表示中の日、ほかの画面なら今日。開始・終了の初期値（`actAddSpan`）は、日付が今日なら、現在時刻を 15 分刻みに切り捨てた時刻から 60 分（23:59 まで）、今日以外は 09:00〜10:00。予定のない時間にも置ける。休みの日にも置ける。「キャンセル」で閉じる。
    - 通知は「切替手順書の作成 の 10:00–11:00 の実績を入れました」（ID でなく件名）。状態を変えたときは「（状態を In Progress にしました）」、Waiting からのときは「（状態を In Progress にしました。待ち先の記録は外しました）」を添える。会議の実績の通知は、確認済みの会議なら「会議の実績を更新しました」、それ以外は「会議の実績を入れました」。
    - 実績の欄（予定の枠と会議で共通。`views/schedule.js` の `actualBox`）: 予定の枠を選んだときの欄（`actualForm`）と、会議を選んだときの欄（`meetingActualBox`）は、同じ部品・同じ場所・同じ並び。外側は `.actform`。並びは、説明の 1 行（「「件名」の実績を入れます」／「…を更新します」。枠は「（予定の枠は残ります）」を添える）、「実績」のラベル（`.aclb`）・日付・開始・終了・ボタン（`.acbtns`。同じ行の右端）。ボタンは「実績を保存」か「実績を更新」（枠は `actual` があるとき、会議は確認済み（`confirmed: true`）のとき）、続けて、あれば「実績を消す」。枠の日付は入力欄（`data-ac="date"`。直せる）、会議の日付は文字（`.acdt`。会議の日付で固定）。時刻の入力欄の属性は、枠は `data-ac`、会議は `data-ma`。`#mtgslot` の中の並びは、`actualForm`（枠の実績の欄か「＋ 実績を追加」の欄）→ 会議の実績の欄 → 会議の編集の欄（`meetingForm`。件名・日付・開始・終了・プロジェクト・参加しない・会議を削除・閉じる）→ 突発タスクの欄 → 枠の削除の確認 → タスクの編集欄。下書き（`S.actDraft`。会議は key `m:<会議の ID>`）は、`change` で、入力欄を含む `.actform` から読む（`el.closest(".actform")`）。出す規則（始まっていない枠・会議、参加しない会議、追加中の会議には出さない）と、保存・消去の動きは、上のとおり。
    - 分かっている性質（トレードオフ）: `#mtgslot` は高さに上限のある、欄の中でスクロールする領域なので、窓の高さが低いと、実績の欄の下の会議の編集の欄は、欄の中でスクロールしないと見えないことがある。会議の編集の欄で会議の日付・時刻を変えた直後は、部分の描き直しなので、実績の欄の日付の文字は、次に全体を描き直すまで古いままのことがある（未確認）。「参加しない」を切り替えたときも、次に全体を描き直すまで実績の欄が残る（保存は `setMeetingActual` が断る）。
    - 確認したこと（Chromium・Playwright、1400×900、`?today=2026-11-25&time=10:15`、デモデータ（`sample.json` の日付をずらして 2 ファイルに分けたもの）を `showOpenFilePicker` の差し替えで読み込んだ）: 予定の枠と会議の実績の欄が、編集の領域の先頭に、同じ並びで出ること（保存ボタンの右端が同じ）。会議の件名を打ち換えてから実績を保存しても、件名が残ること。実績の欄の高さが、予定の枠・未確認の会議・実績のある会議で、どれも 107px であること。実績のある会議のボタンが「実績を更新」と「実績を消す」であること。未確認: 暗い配色、幅 900px、日本語入力（IME）、タッチ操作、会議の日付を編集した直後の実績の欄の日付の表示、窓の高さが低いときの `#mtgslot` の中のスクロール。
    - カレンダー（週・日表示とも。`views/schedule.js` の `sessionBlocks`・`meetingBlocks`・`dayBlocks`）は、実績を持つ予定の枠・会議を、実績の時刻の 1 つのブロックで描く（理由は「設計判断」（`design-decisions.md`））。
      - 実績を持たない予定の枠は、枠の `date` の列に予定のブロック（class `plan`、`data-dragsess`。ドラッグ・下端の伸縮ができる）で描く。
      - `actual` を持つ予定の枠は、予定のブロックを描かず、`actual.date` の列の実績の時刻に、実績のブロックを 1 つ描く（class `act`、`data-actbar`。文字は「実績 HH:MM-HH:MM ✓」、`title` に「予定 M/D HH:MM-HH:MM」）。長さが 60 分以上（`PLAN_NOTE_MIN`）で、予定と違うときは、ブロックの中に予定の日付・時刻を小さな文字（`.pl`）で添える。ドラッグ・サイズ変更はできず、押すと同じ予定の枠を選ぶ（`app.js`）。
      - 影: 予定と実績の日付か時刻が違うときだけ、予定の日付の列の予定の時刻に、点線の影（class `pghost`。枠は `data-ghost`、会議は `data-mghost`。文字は「予定 HH:MM-HH:MM」）を描く。同じ日・同じ時刻なら描かない。影は透明の背景の点線の枠で、列の中でブロックより先に描き、うしろに出す（`dayBlocks`）。ドラッグ・伸縮・`tabindex` を持たず、押すと同じ枠・会議を選ぶ。選択中でも、影には `sel` を付けない（選択の枠は、実績のブロックだけに付く）。
      - 3 つの状態（枠・会議とも、ブロックを分けずに見た目で分ける）: 始まる前は予定の色。過ぎて実績が無いものは、点線の枠と「未確認」。実績があるものは、緑（会議は濃い会議色）と ✓。
      - 実績を持つ枠・会議は、ドラッグで動かせない。予定を動かすときは、先に「実績を消す」（枠は `data-actclear`、会議は `data-mtgactclear`）で、予定のブロックに戻す。
      - 重なり: 同じ日で、実績を持たない予定の枠と、実績の側（実績だけの枠・実績のブロック）が時間で重なるときは、予定を左、実績を右に、幅を半分ずつにして並べる（重ならなければ全幅）。同じ位置に重ねると、後に描く実績が予定を覆い、予定の枠が押せなくなるため（実ブラウザで見つかった）。影は、この判定に入れない（実績のブロックは、自分の影とは割らない）。半分の幅（週表示で約 65px）では、時刻の文字が右端で少し切れる。
      - 枠は、予定の日付か `actual.date` が表示中の日にあれば出す（実績のブロックと影は、片方だけが表示範囲に入っても描く）。サマリーの「実績 N 時間」は、表示中の日付に入る実績の区間の合計。
    - 「今日のタスク」の行は、`actual` を持つ枠を札「実績」に続けて実績の時刻（HH:MM–HH:MM）を出し、予定の時刻を小さく「予定 HH:MM–HH:MM」と添える。実績が予定と別の日のときは、実績の時刻の前に日付を付ける（「実績 M/D HH:MM–HH:MM」。`views/prio.js` の `slotHtml`）。行に出す枠は、予定の日付が今日のものだけ（予定が別の日で実績だけが今日の枠は載らない）。
    - 現在時刻と今日（`views/schedule.js` の `nowLineHtml`・`nowMark`）: 日表示は、表示中の日が今日なら、赤い現在時刻の線（`.nowline`）を引く。週表示は、今日が表示中の週にあれば、全部の列の同じ高さに線を引く（どの列も同じ太さ・同じ色の線（2px、`--bad`）。時刻の軸に時刻の札は出さない。どの線も `pointer-events:none` で、ドロップとクリックを妨げない）。今日が週に無ければ、線を引かない。描いたブロックの区間（実績のブロックは実績の区間）が今を含むブロックに、class `now` と、時刻の前の「いま」（`.nw`、`--bad` の太字）を付ける。外枠は付けない（開始ちょうどは含み、終了ちょうどは含まない）。参加しない会議と影には付けない。週表示の今日の日付の見出しは塗りつぶし（`--accent` の背景・`--on-accent` の文字。休みの印も同じ文字色）にし、今日の列の上端の線は 5px。日表示は、表示中の日が今日なら、見出しの日付を塗りの丸い札（`.dtt`）にする。
    - 確認したこと（Chromium・Playwright、1400×900、`?today=2026-10-20&time=10:15`、`sample.json` に、今日の予定の会議 1 つを足した 2 ファイルを、`showOpenFilePicker` の差し替えで読み込んだ。会議と「＋ 実績を追加」だけ）: 過ぎた会議を選ぶと実績の欄が出て、保存で `confirmed` と `actual` が入り、ブロックに「実績 09:05-09:25」が出ること。始まっていない会議には欄が出ないこと。「＋ 実績を追加」で、選択肢に「件名（プロジェクト名）」が並び、今日の初期値が 10:15〜11:15 になること、重なる時間はエラー、過去の日の空き時間は保存でき、その枠を選んで削除でき、状態は戻らないこと。稼働の画面で、確認済みの会議（60 分 + 実績 20 分）が、実績の時間で数えられること。予定の枠に `actual` を持たせる流れ（同じ条件で、`sample.json` に、今日の 08:00〜09:00 の予定の枠を足した）: 過ぎた予定の枠（未確認）を選ぶと、実績の入力欄に予定の日付・時刻が入り、ボタンは「実績を保存」で「実績を消す」は無いこと。08:10〜09:20 で保存すると、同じ枠に `actual` が入り（予定は変わらず、タスクは In Progress になる）、未確認でなくなり、サマリーの実績が 1 時間 10 分増えること。その枠を押すと、入力欄の初期値が実績の値で、文言が「実績を更新」になり、「実績を消す」が出ること。08:15〜08:45 で更新すると、重なりのエラーにならず、サマリーが 30 分になること。開始が今より後（11:00）の保存は、エラーの通知で、`actual` は変わらず、入力が欄に残ること。「実績を消す」で、`actual` だけが外れ、予定の枠は残る（未確認に戻る）こと。サンプルの枠 S8（予定 09:00〜10:00、実績 09:10〜10:10）の週のサマリーの実績が 3.0 時間（S1 の 2 時間と S8 の 1 時間）になること。実績つきの枠の「削除」は、「実績 40 分も消えます」の確認が出て、「やめる」では何も変わらず、画面を移ると確認が消え、「削除する」で枠が消えること。未確認（コードとテストだけ）: 予定を別の日へ動かしても実績が動かないこと、今日のタスクの札の見た目。そのほか未確認: 暗い配色、幅 900px・700px、実際の日本語入力（IME）、タッチ操作、枠・実績のブロックのキーボードでの選択、重なりのエラーの文言が「他の実績の枠」と「他の実績」の 2 種類あること。
    - 確認したこと（実績の 1 つのブロック・影・現在時刻。Chromium・Playwright、1400×900、`?today=2026-11-25&time=10:15`、デモデータ（`sample.json` を日付をずらして 2 ファイルに分けたもの）を `showOpenFilePicker` の差し替えで読み込んだ）: 週表示で、赤い現在時刻の線が今日の列に出て、今日の見出しが塗りつぶしで、凡例に「現在時刻」「会議の実績(✓)」「実績とずれた予定」が出ること。進行中の会議（10:00-11:00）に「いま」の文字が付き、現在時刻の線が横切ること。未確認の会議（朝会 09:00-09:30）に実績 09:05-09:40 を保存すると、実績の時刻の 1 つのブロック（`data-mact`）と、予定の時刻の点線の影（`data-mghost`）になること。「実績を消す」は実績を入れるまで出ず、押すと、未確認の見た目と、ドラッグできる会議（`data-dragmtg`）に戻ること。予定と別の日に実績がある枠（11/24 の 11:30-13:30。予定は別の時刻）が、実績の日に 1 つのブロックとして出て、予定の時刻が文字で添えられること。未確認: 週表示の今日以外の列の線と、外枠を外した「いま」のブロックの見え方（テストだけ。暗い配色を含む）、予定の枠の実績が、予定と同じ週の別の時刻にあるときの見え方（実機）、暗い配色、幅 900px・700px、日本語入力（IME）、タッチ操作。
  - Done・Cancelled は薄く、ボタン無しで末尾に出る。
  - 未完了で重要（`isImportantMark`）のタスクには、状態 pill の直後に紫の「重要」バッジ（`impbadge`。12px の太字、角の丸い帯）が付く（Done・Cancelled には付けない）。「この週のタスク候補」では、重要の理由の文字の代わりに、同じバッジを理由の欄の先頭に出す。右の列の幅（約 300px）で行からはみ出さないことは、Chromium で確かめた。
  - 今日のタスクに入ったタスクは、`renderPrio` が一覧から除く（`rankTasks` は変えない）。
  - スケジュール画面（`renderSide` の `sched: true`）では、今日のタスクの終わっていない行（Done・Cancelled 以外）も、「この週のタスク候補」の行と同じ `draggable="true" data-dragtask`（`cursor: grab` も同じ）を持つ。カレンダーへ落とすと、同じタスクの予定の枠がもう 1 つ増える（右の列の候補から除かれたタスクを、2 つ目の枠として置くため。落とした先の処理は、右の列の候補の行と同じ `planDrop` / `addSession`。重なり・休みの日の検査も同じ）。ガント・リスト・プロジェクト画面の右の列の行は、ドラッグできない。確認したこと（Chromium・Playwright、1500×1000、`?today` なし、デモの 2 ファイルを `showOpenFilePicker` の差し替えで読み込んだ）: スケジュール画面で、すでに今日に枠のあるタスクの行をカレンダーの今日の列の空いた 11:00 へドラッグすると、同じタスクの 2 つ目の枠ができ、行の時間が 3 つ並ぶこと。ガントの右の列の行に `draggable` が無いこと。未確認: 実際のマウス操作、ボタンの上からドラッグを始めたときの動き、重なり・休みの日に落としたときの画面の動き（単体テストと同じ `addSession` の検査）。
  - 日表示の作業枠は、ボタンの代わりにタスクの状態の文字を出す。
- まだ開始していない予定枠があるときの確認（`doneAskHtml`）は、対象が今日のタスクにいればパネルの行に、いなければ（リストの select から）リストの行に出る。解除されるのは開始前の予定枠だけ（`futurePlanned`）。進行中の枠は残り、終わったあとに実績にできる。実績（`actual`）を持つ枠は、未来へ動かしてあっても解除せず残す（実績を更新・消す入口を残すため。`validate` の「Done なのに未来の予定枠」の警告も、その枠には出さない）。

## ToDo タブ

- 画面は `ui/views/todo.js` の `renderTodo`。タブは、スケジュールと稼働の間（`tab-todo`）。上に 2 列（`.tdcols`。幅 700px 以下は縦に 1 列）を並べ、左が「今日の ToDo（M/D）」、右が「この週のタスク候補」（週の移動と、表示中の週のタスクの一覧）。期間のタスクの表は、ToDo タブに出さない（稼働タブ。「会議と稼働」）。完了の入力欄は、行の下に開く。選択の状態は、メモリだけに持つ（`S.todoWeek`（表示中の週の月曜日）・`S.tdOpen`（完了の入力欄を開いているタスクの ID か `null`）・`S.tdCol`（入力欄を開いた列。`"today"` か `"week"`）・`S.tdDraft`（入力欄の下書き）・`S.tdPlan`（「今日へ」の入力欄。`{ key: タスクの ID, start, minutes }` か `null`）・`S.tdChase`（催促の入力欄。`{ key: タスクの ID, mode: "done"|"edit", days, party, expected }` か `null`）・`S.urgentDraft`（突発タスクの入力欄。スケジュール画面と共通）。保存しない）。
- データ: 一覧は保存せず、タスクの期限・状態・作業枠から計算する（理由は「設計判断」（`design-decisions.md`））。規則は `core/week.js`（`todayTasks`・`weekTasks`・`rangeTasks`・`chaseTasks`・`mondayOf`）。この一覧のために個人ファイルに持つものは無い。
- 移動: 週（← → 今週）。右の列の見出しのすぐ下に置く。「この週のタスク候補」の週だけを動かす（稼働タブの期間は、稼働で見ている日（`S.wdate`）で決まり、この移動では変わらない）。左の列は、表示中の週によらず、いつも今日。週を動かすと、開いている完了の入力欄と「今日へ」の入力欄を閉じる（左の列の欄も。`moveTodoWeek`）。画面の移動（`clearSel`）でも閉じる。読み直しなどで、開いているタスクがデータから無くなったとき・`S.tdCol` が `"today"`・`"week"` 以外のときも閉じる（`render()`。「今日へ」の入力欄は、タスクが無くなったときだけ）。
- 今日の ToDo（`todayTasks(data, today)`）: 今日の日付に、予定の枠か、実績の区間（予定の枠の `actual.date`・実績だけの枠）があるタスク。Cancelled は出さない。1 つのタスクは 1 行。
  - 行は、右の列と同じ部品（プロジェクト名・件名・状態・前のタスク待ち・期限・チェックの進捗・今日の予定の分と実績の分）に、今日の枠の札と時刻（`.td-slots`。札は「今日のタスク」と同じ `slotHtml`）を足す。今日の予定の枠は予定の時刻で、`actual` があれば札「実績」（実績が別の日なら「実績 M/D HH:MM–HH:MM」で、未確認にならない）。予定が別の日で実績が今日の枠は、実績の時刻で札「実績」。
  - 枠の並びと、タスクの並びの鍵は、今日に見せる時刻（実績が今日なら実績の開始、ほかは予定の開始）。Done 以外を最初の枠の開始の昇順（同じなら ID の順）、Done を末尾。
  - 行が 0 件なら「今日の枠のあるタスクはありません。」。右の列と同じタスクが両方に出てもよい（重複を除かない）。
- この週のタスク候補（`weekTasks`）: 週は月曜〜日曜。Cancelled のタスクは、どの週にも出さない。1 つのタスクは 1 行だけで、次の組のうち、最初に当たるものに入る。
  1. 期限超過: 未完了（Done・Cancelled 以外）で、期限が今日より前。
  2. 今週に予定あり: 未完了で、その週の日付に、予定の枠か実績の区間（`actualSpans`）がある（期限は週より後でもよい）。
  3. 今週の期限: 未完了で、期限が週の終わり以前。期限の無いタスクは、枠か実績が無ければ出ない。
  4. 完了: Done で、`doneAt` が週の中か、その週の日付に予定の枠か実績の区間がある。
  - `weekTasks` の組の中は、期限の昇順（期限なしは最後）、同じなら ID の順。画面では、未完了の行（期限超過・今週に予定あり・今週の期限）を、組の見出しなしの 1 つの一覧にして、優先順位（`rankTasks`）の順に並べる（別の週でも今日の点数の順。順位に無い行は末尾）。各行の `td-meta` の上に、`rankTasks` の理由を「・」でつなぎ、予定ありの組の行は先頭に「今週に予定あり」を足す。完了の組だけ、見出し「完了」の下で末尾に出す。行が 0 件なら「この週のタスクはありません。」。
  - 過去の週・未来の週も、同じ規則で計算する。「その週の終わりに未完了だったか」は、今の状態で近似する（状態の履歴を持たない）。
  - 前のタスクのうち、データにあって完了していないものが 1 つでもあるタスクも、同じ規則で出し、行に「前のタスク待ち」の札を添える。
  - 今日の ToDo に登録済みの候補: 今日の日付に作業枠（予定・実績）がある、未完了の候補（`todayTasks` に載るもの）は、見出し「今日の ToDo に登録済み（N 件）」の組にまとめ、未登録の一覧のあと・完了の組の前に出す（件数は、その組の行数）。未登録の行は、これまでどおり優先順位の順。登録済みの行は、同じ順で、背景を沈ませ、先頭に ✓（`.regchk`）、今日の枠の時刻と札（`slotHtml`）を付け、理由は出さない。ボタンは「もう 1 枠入れる」（`data-tdplan`。「今日へ」と同じ入力欄を開く。同じタスクの枠を、もう 1 つ足せる）と「編集」。保存する値は持たず、今日の枠から導く。見る週によらず、今日（`today`）の枠で判定する。
  - 行に出すもの: プロジェクト名（無ければ「プロジェクトなし」）・件名・状態の札（`statusPill`。右の列と同じ）・期限・チェックの進捗（M/N。チェックリストがあるときだけ）・その週の予定の分（自身の予定の枠。`actual` を持つ枠も数える）と実績の分（自身の実績の区間）。ID は出さない。完了の組の行は薄く、件名に取り消し線を付け、「完了」のボタンを出さない。
  - 手で一覧に足す・外す操作は、持たない（「今日へ」・突発タスクは、今日の予定の枠を足す操作で、一覧はその枠から導く）。
- 完了の入力欄: 左の列の行の「完了」と「今日の分を完了」（どちらも `data-tdopen`。押した列を `data-tdcol`、種類を `data-tdmodeopen`（`done`・`today`）で持つ）を押すと、その列のその行にだけ入力欄が開く（左右に同じタスクがあっても 1 つだけ。同時に 1 行だけ。同じ列の同じ行の同じボタンをもう一度押すと閉じ、別の列・別のボタンなら開き直す）。開くと、開始の欄にフォーカスする。右の列（この週のタスク候補）の行には、「完了」を出さない（完了にするときは、左の列の行か、「編集」の状態の欄で行う）。右の列の「今日へ」と、ガントチャート・リストの右の列には「今日へ」を出さない（ガント・リストの右の列は、ToDo タブへ移らず、見るだけ）。欄の上の切り替え（`data-tdmode`。`S.tdMode`）で、「今日の分を完了」と「タスクを完了」を行き来できる（入力は残す）。
  - 「今日の分を完了」（`S.tdMode` が `today`）: 実績の日付・開始・終了（3 つとも必須）だけを、`edit.js` の `completeToday` で書く。状態の欄は出さない（「状態は変えません」）。タスクの完了・チェック・未来の予定の枠は変えない（To Do・Waiting は、実績の規則で In Progress になる）。完了したタスクは断る。3 つが揃わなければ、何も保存しない（通知だけ）。実績の書き方は `completeTask` と同じ（`recordDayActual`）。
  - 「今日の分は完了」の印（左の行。`pill.tdone` と薄い背景 `li.part`）: 今日の実績がある（今日の日付の `kind: "actual"` の枠、または今日の日付の `actual` を持つ予定の枠がある）未完了のタスクの行に付ける。保存する値は持たず、実績から導く。そのため、「今日の分を完了」を押さずに実績を足したタスクにも付く。残りの予定の枠があっても付く。印が付いても、「今日の分を完了」ボタンは残す（実績を足せる）。右の列の行には出さない。
  - 「実績を外す」（`data-tdactclear="<枠の ID>"`。左の列の行の、実績のある枠の横）: 予定の枠なら、実績（`actual`）だけを外し、予定の枠は残す（`clearActual`。スケジュールの「実績を消す」と同じ）。実績だけの枠（`kind: "actual"`）は、外す先の予定が無いので、枠ごと消す（`removeSession`。確認は出さない）。状態は変えない（実績で In Progress になっていても戻さない）。外すと、今日の実績が無くなれば「今日の分は完了」の印も消える。右の列の行には出さない（枠の時刻を出さないため）。
  - 実績（省略できる）: 日付・開始・終了（`data-tf`）。日付の初期値は、左の列では今日。右の列では、今日が表示中の週にあれば今日、なければ週の月曜日。開始・終了の初期値は、その日のそのタスクの、`actual` の無い予定の枠のうち、始まっている（開始が今以前の）もので、開始の早いものの時刻。なければ空（始まっていない枠の時刻は、そのまま保存すると「開始が今より後」のエラーになるため）。
  - 状態（`data-tf="status"`）: To Do・In Progress・Done・Cancelled から選ぶ（Waiting は選べない）。初期値は Done。
  - チェックリスト: ガント・リスト・スケジュールの編集欄と同じ部品（`views/checklist.js` の `checklistEditorHtml`。並べ替えの取っ手・チェック・文言を直せる欄・「×」・末尾の追加の欄。チェックリストが無いタスクにも追加の欄が出る）と、「残りをすべてチェック」（`data-tdckall="<タスクの ID>"`。「タスクを完了」のとき、項目があるときだけ）。チェックの付け外し・文言の直し・追加・削除・並べ替え・「残りをすべてチェック」は、操作のたびに、すぐタスクへ保存する（「保存」を待たない。`apply` 1 回ずつ。操作は、ほかの画面と同じ `data-ck*` のハンドラ）。`apply` は、完了の入力欄が開いていれば、描き直しの前に、欄の値（日付・時刻・状態）を下書き（`S.tdDraft`）へ写すので、入力は残る。状態が Done のとき、未完了の項目が残っていれば、`completeTask` が「未完了の項目があります。チェックするか、削除してください」のエラーにし、何も保存しない（理由は「設計判断」（`design-decisions.md`）の、Done のチェックの警告の項目）。Done 以外と、項目の無いタスクは止めない。エラーのあとに欄が開いたまま入力が残ることは、実機では未確認。
  - 「Done・Cancelled にすると、未来の予定の枠 N 件を解除します」の注意は、解除される枠（`futurePlanned`）が 1 件以上あるときだけ出す（状態の欄の選択によらない）。
  - 「保存」（`data-tdsave`。「タスクを完了」のとき）は、`edit.js` の `completeTask` で、実績・状態・（`checks` を渡したときの）チェックを 1 回の保存（`apply` 1 回）で書く。画面は `checks` を渡さない（チェックは、操作のたびに保存済みのため）。入力欄の値は、`views/todo.js` の `completeInput` で入力にする（「今日の分を完了」は、その `actual` だけを使う）。開始・終了がどちらも空なら、日付が入っていても実績は送らない（日付は初期値で埋まるため）。片方だけなら送り、`completeTask` の検査で止める。
  - `completeTask` の順序: 実績（実績の日付に、そのタスクの `actual` の無い予定の枠があれば、開始の早い枠の `actual` に書く（`recordSlotActual`）。なければ実績だけの枠を足す（`recordActual`）。規則は「実績を保存」と同じで、開始が今より後・実績の区間の重なりは不可）→ 状態（`updateTask`。実績による In Progress への自動変更より、選んだ状態が優先）→ チェック → Done・Cancelled なら、未来の予定の枠を解除（実績を持つ枠は残す）→ Done なら、定例の次回を作る（`spawnNextRepeat`）。1 つでも検査に通らなければ Error で、何も保存しない。
- 編集: すべての行（左右の列・Done の行を含む）の「編集」（`data-tdedit`。押した列を `data-tdcol`）で、その行の下に、スケジュールと同じ編集欄（`renderTaskEditPanel`。`S.taskEdit` と、開いた列 `S.tdEditCol`）を開く。同じ行をもう一度押すと閉じる。「詳細を開く」「リストで開く」（`data-goto`。リスト画面へ移り、そのタスクの行を強調する。ガントの窓と同じ処理）「閉じる」「削除」と、状態の欄の待ち先・Done の確認（`S.pendingWait`・`S.pendingDone`）は、スケジュールと同じ。項目を直すと、その場で保存する。開いている間は、行をドラッグできない。完了・今日へ・催促の入力欄を開くと、編集欄は閉じる（逆に、編集欄を開くと、それらの入力欄も閉じる）。

## 会議と稼働

- 予定表から取得した会議は、「参加しない」とプロジェクトだけ変更できる。
- 「参加しない」の会議（`skip: true`）は、スケジュール画面の右上の「参加しない会議」ボタンで、カレンダーに出す・隠すを切り替える。初めは隠す。隠すと、週・日の両方で描かず（選択中の会議だけは出す）、凡例の「参加しない会議」も出さない。稼働の計算とデータは、出す・隠すで変わらない（どちらでも、稼働に数えず、作業枠と重なっても注意しない）。状態は `S.prefs.showSkipped`（`prefs.js`）に持ち、`localStorage`（`project-lens.prefs`）に保存する。`data.json` には保存しない。
- 会議のプロジェクトは、規則（件名のキーワード → プロジェクト）で自動に付き（`projectBy` が `rule`）、手動で付けたもの（`manual`）は規則を変えても動かない。
- 稼働の期間は、日・週・月（切り替えのボタンの並びも、日・週・月）。範囲は `core/workload.js` の `periodRange`（日はその日だけ、週は月曜〜日曜、月は月初〜月末）。前後のボタンは、日は 1 日、週は 7 日、月は 1 か月ずつ動かす（`views/workload.js` の `shiftWorkloadDate`）。見出しは、日が `2026/10/20(火)`、週が `10/19〜10/25 の週`、月が `2026年10月`。今日へ戻すボタンは、「今日」「今週」「今月」。期間の選択（`S.wperiod`、初めは日（今日）。`renderWorkload` の `period` の既定も日）と表示中の日（`S.wdate`）は、メモリだけに持ち、保存しない。確認したこと（Chromium・Playwright、`?today=2026-10-20&time=10:15`）: 日・週・月の切り替え、日の前へ・「今日」、各期間の合計。
- 稼働のタスクの集計（`views/workload.js`。`renderWorkload` が、時間の表の列と、末尾の「タスク」の表に使う）: 期間は、稼働の日・週・月（`periodRange`）に従い、見ている日（`S.wdate`）と期間のボタンで動く。ToDo タブの週の移動（`S.todoWeek`）とは別。行は `core/week.js` の `rangeTasks(data, range, today)`（`weekTasks` と同じ規則・並びを、週ではなく任意の期間 `{start, end}` で求める。Cancelled は出ない）。
  - 期限超過は today 基準: 期限が今日より前で未完了のタスクは、どの期間を見ても「期限超過」の組に出る（過去の月を見ても、今も遅れているタスクが載る）。「期限」の組は、期限が期間の終わり以前のもの。
  - プロジェクト別の表: 既存の列（タスク・会議・合計・内訳）に、「完了」（`done / total 件`。`progressByProject`。Done の行が done。行が無ければ「—」）と「進捗」（棒）を足す。合計の行は、期間の行全体を数える。プロジェクトなし・存在しないプロジェクトのタスクは、「プロジェクト未設定」の行に寄せる（時間が 0 でも、タスクがあれば行を出す）。
  - 「タスク」の表: `rangeTasks` の行ごとに、プロジェクト・タスク・進捗（M/N。チェックリストが無ければ「—」）・予定・実績（分）。行が無いときは「この期間のタスクはありません。」。
