# 画面の動き: ガントチャートとリスト

画面全体の構造と、ガントチャート・リスト。[開発者向けの情報](../development.md)の一部。

画面上部のナビは、ガントチャート・リスト・スケジュール・稼働・設定の 5 つ。`S.screen` が `gantt`・`list`・`schedule`・`workload`・`settings`（初期値は `gantt`）で、保存はしない。ガントチャートとリストは、同じ `renderProjects`（`opts.view`）で、絞り込み・「完了を隠す」の状態を共有する。画面内の「ガント／リスト」の切り替えボタンは持たない（`S.pview` は廃止）。

## 全体

- ヘッダー、ガントチャート・リストのフィルタの行、右側の列（今日のタスク・この週のタスク候補）は、スクロールしても上端に固定する（CSS の `sticky`。ヘッダーの高さを `--hh`、フィルタ行の高さを `--th` に入れて、下の帯が、その下に付く）。固定表示は、画面のスクロールに対して、CSS の `position: sticky` で付ける（JS でずらさない。ずらすと、画面のスクロールが先に動き、日付が遅れて動いてから戻る）。新しい CSS は、`theme.css` の末尾の節にまとめ、すべて `#view` の中に限る。
  - **絞り込み行（`.ptool`）**: プロジェクトのチップは 1 行に収め、横にスクロールする（`.chips-row`。`flex-wrap:nowrap; overflow-x:auto`）。プロジェクト名のプルダウン（`data-projectpick`。完了も含む全プロジェクト）と「＋ プロジェクトを追加」は、スクロールの外（`.ptool-end`）で固定。チップは、状態が「完了」のプロジェクトを出さない（選択中のあいだだけ出す。完了のものは、プルダウンから選ぶ。「完了を隠す」ボタンの基準（全タスクが Done も含む）とは違い、プロジェクトの状態だけで決める）。大項目で絞り込む機能（`S.group`・`data-groupfilter`・`renderGantt`/`renderList` の `group` オプション・`groupNames`）は、利用者の希望でやめた（プルダウンに置き換えた）。各タスクの大項目・中項目の表示と編集は残る。プロジェクトが何件でも、固定の高さ（`--th`）は 49px のまま（30 プロジェクトで、折り返していたときは 231px。実測）。スクロールバーは出さない（`scrollbar-width:none`）。出すと、チップがあふれたとき、固定の行が 15px 高くなり、プロジェクトの数で高さが変わるため。代わりに、マウスの縦のホイールで横に動かし（`wheel`）、横スワイプ・Tab でも動く。デメリット: スクロールバーがないため、マウスだけの利用者は、ホイールを回すまで、あふれていることに気づきにくい。描き直しでは、チップの行の横位置を保ち、選択中のチップが見えなければ、行の中だけを動かす（`scrollIntoView` は、ページの縦も動かすので使わない）。
  - **ガント**: プロジェクトごとに、`section.pg` の中を、`.pgstick`（プロジェクトの見出し `.pg-head`。`sticky`、`top: --hh + --th + --gh`。`--gh` は操作の帯 `.gtop` の高さ）と、`.gwrap`（`.gstrip` + `.gscroll`）に分ける。`.gscroll` は横だけにスクロールする（`overflow-x:auto; overflow-y:hidden`）。`.gstrip` は、本物の日付軸（`.g-head .g-lane`）の写し（左の空き `.gsl` + 窓 `.gsv`）で、`sticky`（`top` に `--pgh`、見出しの高さ）。次のプロジェクトに入ると、見出しと複製が入れ替わる（`sticky` の動き。`section.pg` が範囲）。`data-todayfrac`・`data-s0`・`data-span` は、全プロジェクト共通の値を、各 `.gscroll` に付ける（ドラッグ・今日へ移動が `.gscroll` から読む）。
  - `.gwrap` は `padding-bottom: --sh + --sb`、`.gscroll` は同じ分の負の `margin-bottom`、`.gstrip` は `margin-bottom: -(--sh)`: 流れの高さを増やさず、`sticky` の範囲を複製の高さ（`--sh`）と横スクロールバーの高さ（`--sb`）だけ短くする。複製が、プロジェクトの下端（横スクロールバーを含む）を越えて、下のものに重ならない（`--sb` を除かなかったところ、複製の下端が表・枠の横スクロールバーの 15px に重なった。実測）。複製の目盛りの行は、本物の行の `column-gap`（12px）だけ右へ置く（測らないと、12px ずれた）。
  - 再描画（`render`）のとき、ガントの横位置（`scrollLeft`。全プロジェクトで同じ）とページの縦の位置（`scrollY`）を保つ。描き直しの間、`#view` に `min-height` を付けて、ページが縮んで `scrollY` が飛ぶのを防ぐ。`#view{overflow-anchor:none}`: 切らないと、ブラウザのスクロールアンカーが、描き直しのたびに縦の位置を +2px ずつずらした（実測）。`alignGScrolls` は、動かした枠の `scrollLeft` を他の枠にそろえる。代入で起きる `scroll` は無視する（`WeakMap` の `aligned`）。無視しないと、動いている最中の枠を、古い位置へ引き戻した（「今日へ移動」が 1px で止まった。実測）。「今日へ移動」のなめらかなスクロールは、先頭の枠だけに掛け、他の枠は `alignGScrolls` が追う。
  - **リスト**: プロジェクトの見出し全体は、`section.panel` の直下の `.pstick` にあり、`sticky`（ヘッダー・フィルタ行の下）。中身は、名前と状態の行 `.prow`（編集できる入力欄 `data-pf="name"`・`data-pf="status"`）と、その下の `.phead`（種別・開始・期限・進捗・稼働・注意の印）。利用者の希望で、注意の印（期限超過など）も固定する（印が折り返すと、固定の高さが増える）。未測定: 印が折り返したとき（3 行など）の高さ。画面の高さが低い（500px 前後）と、固定部分が増え、表の見える高さが減る（上限や折りたたみは足していない）。Tab で表の入力欄にフォーカスすると、固定部分の裏に隠れうる（`scroll-padding-top` がない。未実測）。列見出しは、表を包む `.twrap` の先頭の**複製**（`.thstrip`、`aria-hidden`。`renderList` が空で出し、`syncThStrips` が、本物の `thead` の各列の幅・余白・文字を測って写す）で固定する。`.thstrip` は `sticky`（`top: --hh + --th + --ph`。`--ph` は `.pstick` の高さで、`syncThStrips` が `section.panel` に入れる）。`.twrap` は表だけを含む（マイルストーン・履歴は外）。`padding-bottom: --sh + --sb` と、表の枠の負の `margin-bottom` で、`sticky` の範囲を短くし、複製が表の下端を越えない。固定していないときは、本物の `thead` に重なる（差 0px）ので、出し分けの JS（`thStripOn`・`updateThStrips`）は持たない。横スクロールの位置は、表の枠の `scroll` イベントで、複製の `translateX(-scrollLeft)` にそろえる（横方向だけ JS）。本物の `thead` が非表示（幅 860px 以下）のときは、複製を空にする（`:empty` で隠れる）。複製は、描き直し・画面の大きさの変更のたびに（`syncSticky` から）作り直す。リストの表は `pinTableHeads` の対象外。
  - 設定・稼働の表（`.tscroll` で `.tlist` でないもの）の列見出しは、従来どおり `pinTableHeads` がずらす。
- 右の列の開け閉め（`showPrio`）は、このブラウザに保存する。本体と右の列の境界線の取っ手（`.side-toggle`、`data-pref="prio"`）で行う。閉じても取っ手は残る。幅 900px 以下では、列が 1 つに回り込み、取っ手は横長の帯になる。取っ手の名前に「この週のタスク候補」が入るので、パネルの有無は見出しの id（`h-rk`・`h-td`）で見る。
- **読み込み中のファイルの札（ヘッダー）**: 「更新」のとなりに、札を 2 つ出す（共有・個人。`renderFileChips(data, info, open)`、`views/filechips.js` の純関数）。札は、点（書き込める＝緑、読み込み専用＝橙）・「共有」か「個人」・ファイル名。ファイル名が分からないときは「選んだファイル」。
  - 詳細（札を押すと、その札の下に開く）: 共有は、ファイル名・プロジェクト（先頭 3 件の名前。4 件以上は「ほか N 件」）・タスク（N 件、うち Done M 件）・更新日時・保存。個人は、ファイル名・作業枠・実績（`sessions` と `orphanSessions` の合計件数）・会議（`events` の件数）・更新日時・保存。どちらも、末尾にボタン「別の共有ファイルを選ぶ」・「別の個人ファイルを選ぶ」（`data-open`）を持つ。ヘッダーに直接置いていた同名のボタンは、詳細へ移した（ファイルを開いていない画面の案内とボタンは、そのまま）。
  - 更新日時は「YYYY/MM/DD HH:MM」（ローカル時刻）。`store` が持つ、読み込み（または直近の保存）時点のファイルの更新日時を使う。「更新」で読み直すと変わる。分からなければ「—」。
  - 保存は、直接保存できるブラウザ（`showOpenFilePicker` がある）でハンドルを持っていれば「書き込めます」、そうでなければ「読み込み専用」（複数選択の入力欄で開いたとき）。
  - `store.info()`: 今のファイルの `{ name, at }` を返すだけで、何も変えない（読み書き・競合検知の動きは変わらない）。`createPairStore` の `info()` は `{ shared, personal }`。入力欄で開いたファイル（ハンドルが無い）の名前と更新日時は、選んだときに `S.chosenFiles` へ控え、`app.js` の `fileInfo()` が `info()` の代わりに使う。
  - 開閉は `S.fileInfo`（`"shared"`・`"personal"`・`null`。メモリだけ。同時に 1 つ）。札（`data-fileinfo`）を押すと開き、同じ札をもう一度押すと閉じる。閉じるのは、ほかに、詳細の外を押したとき、画面（タブ）を移ったとき、「別のファイルを選ぶ」を押したとき、Escape。閉じる処理（`closeFileInfo`）は、描き直さない（打ちかけの入力を消さないため）。Escape は、開いていれば詳細だけを閉じ、そこで終わる（開いている入力欄の下書きの破棄は、次の Escape）。
  - 置き場所: 詳細は、`.filebar` を基準に絶対配置し、押した札の真下（札の下端から 6px）に、左端を札の左端にそろえて置く（`placeFileInfo`。描画のあとと、ウィンドウの大きさを変えたときに計算する。札が 2 行目に折り返しても、その札の下に出る）。画面の左右 16px の余白からはみ出すときは内側へ寄せ、幅が 392px に満たない画面では、詳細の幅（360px）を縮める。
  - 確認したこと: ブラウザ（Chromium、デモデータ）で、札の表示・詳細の開閉（札を押す・外を押す・Escape・別のファイルを選ぶ）と、幅 1400・900・700・420px で、詳細の左端が札の左端と一致するか（はみ出すときは内側へ寄る）、画面の内側に収まることを確かめた。未確認: ダークテーマでの見え方、`showOpenFilePicker` の無いブラウザでの札と詳細（`S.chosenFiles` の経路）。
- URL に `?today=2026-10-20&time=10:15` を付けると、現在日時を固定して開ける（動作確認用）。
- **日付の欄**: 画面の日付の欄（リストの開始・期限・回答予定日、ガントの窓とスケジュールの編集欄の開始・期限、プロジェクトの開始・期限、マイルストーンの日付、会議と突発タスクの日付、設定の休みの開始・終了と営業日）は、すべて `common.js` の `dateInputHtml` で描く。文字の欄（`type="text"`・`data-date`）に、`2026/10/20`・`2026-10-20`・`20261020`・`2026/1/5`・`2026年10月20日`（全角の数字、`2026.10.20`、日本語入力で出る区切り `・` `ー` `‐` `−` `–` `—` `。` `．` `、` `，`、空白も可。区切りは数字の組の間だけ）を打てる。横の「📅」（`data-datepick`）は、隠れた `type="date"` の欄（`.dpick-in`）に今の値を入れて `showPicker()` で選択を開き（使えないときは、その欄に focus して click）、選んだ日を文字の欄に写して、文字の欄の `change` として流す。利用者の判断: 年・月・日を区切って打つブラウザの日付の欄では、`2026/10/20` を一度に打てないため。データは、これまでどおり `YYYY-MM-DD`。
  - 確定（`change`。休み・営業日の追加は Enter の `keydown` も）は、`app.js` の `normalizeDateField` が、`#view` のキャプチャ段階で、ほかの処理より先に行う: 読めれば `el.value` を `YYYY-MM-DD` に直し（`core/dates.js` の `parseDateInput`。実在しない日・年が 4 桁でないものは読めない）、以後の処理は、これまでどおり `el.value` を読む。読めなければ、元の値（`defaultValue`）に戻し、欄を赤い枠（`.bad`）で少しの間示し、「日付は 2026/10/20 の形で入力してください」と通知して、その確定をほかの処理に渡さない。空は、欄ごとのこれまでの扱いのまま通す（開始・回答予定日は外す、期限・会議の日付はエラーなど）。
  - 確認したこと（Chromium・Playwright、1400×900、`?today=2026-10-20&time=10:15`）: リストの期限に `2026/12/25` を打って Tab で `2026-12-25` が保存されること、`abc` で通知が出て元の値に戻ること、`20270105` で `2027-01-05`、「📅」を押してもエラーにならず、隠れた欄の `change` で `2027-01-15` が保存されること、設定の休みに `2026/11/2` を打って Enter で追加されること。未確認: ブラウザの日付の選択の見た目（自動のテストでは開いた画面を撮れない）、Edge・Firefox、日本語入力（IME）で全角の数字を打ったときの確定、ガントの窓・会議・突発タスク・営業日の欄の画面での確定（同じ処理を通ることは、描画のテストとコードの結線のテスト）。

## ガントチャートとリスト

- **プロジェクトの区切り（カード）**: ガントも、リストと同じく、プロジェクトごとに 1 枚のカードにする（利用者の希望）。`section.pg` に、リストのカード（`section.panel`）と同じ線（1px の `--line`）・角丸（10px）・背景（`--surface`）・左右と下の余白（16px）を付け、カードの間を 16px 空ける（リストの縦の並びの `gap` と同じ）。操作の帯（`.gtop`）も 1 枚のカード。外側の `section.panel` は、線・背景・余白を持たず、`.gtop` の `sticky` の範囲（全プロジェクト）としてだけ残す（`.gtop` を各カードの中へ移すと、プロジェクトごとに帯が入れ替わるため）。カードの上の余白は `.pgstick` の `padding-top`（18px）に持たせ、固定したときも見出しの上に同じ余白が残る。プロジェクトなしの区切りも同じカード。マークアップは変えず、CSS（`theme.css` の末尾の節）だけで分ける。確認したこと（Chromium・Playwright、1400×900、`?today` なし、デモの 2 ファイルを `showOpenFilePicker` の差し替えで読み込んだ）: カードの間は 16px（リストも 16px。変える前のガントは 0px で、`section.pg` の下の線だけ）。`.gtop` の上端は、スクロール 0・400・1000px のどれでも 115px（ヘッダーとフィルタ行の高さの和。変える前は先頭で 115.4px）。`.pgstick` の固定の位置は 228px（`.gtop` の高さが線の分 1px 増えた。変える前は 227px）で、次のカードの上端がそこへ来ると入れ替わり、日付軸の複製（`.gstrip`）はその下（300px）に固定される。1 つのプロジェクト・プロジェクトなしだけに絞ったときも、カード 1 枚で同じ位置に固定される。横スクロールのそろえ（`alignGScrolls`）・「今日へ移動」が全カードで同じ `scrollLeft` になり、前のタスクの線（`.gdeps`）はカードごとに描かれる。1 枚目のカードの見出しは、先頭（245px）から約 17px（カードの間と線）動いてから固定される（`.gtop` の下にカードの間を置いたため。リストの 2 枚目以降のカードと同じ動き）。未確認: 暗い配色、幅 900px 以下。
- ガントチャートは、土日・手動の休み（`settings.holidays`）・日本の祝日の列に、同じ着色（`.gwk`）を付ける。判定は `core/holidays.js` の `restDayChecker`。「土日祝を営業日に数える」の設定に関わらず着色する（日数の計算と作業枠にだけ効く設定のため）。営業日の指定（`workdays`）の日は着色しない。日表示（40 日以下の表示）のときだけ着色する（土日の着色と同じ）。
- 前のタスクの線は、編集画面のガントチャートだけに出す。`gantt.js` が、前のタスクのあるバーに `data-pre`（空白区切りの ID）を付け、`ui/deps.js` が、描画のあとにバーの位置を測って SVG（`.gdeps`）を重ねる。両端のバーが同じプロジェクトの表に出ているものだけ引く（「完了を隠す」で隠れた行・別のプロジェクトとの線は引かない）。バーのドラッグ中は、線がずれるので隠す。バーにマウスを置くと、`focusDeps` が、そのタスクを青、前のタスクを橙にし、つなぐ線を濃くし、ほかを薄くする。前のタスクも次のタスクもないバーは、自身だけを青にする（ほかは薄くしない）。
- ガントのラベルの ID の列は `56px`（`AA-0001` が等幅 11px で収まる幅）。幅 1400・900・600px で件名が詰まらないか、固定表示（`.gstrip`・`.thstrip`）がずれないかは、ブラウザで未確認。幅 640px 以下は、ラベルを 150px、ID の列を 40px（`--idw`）、ID の字を 9px にする（件名の列は、並べ替えの行で約 65px、ほかの行で約 80px と計算した。実測はしていない）。
- 開始日（`taskStart`）は、`start` があればそれ、なければ前のタスクの期限の最大値、それもなければ期限。前のタスクがあるタスクにも左端のつまみを出し、ドラッグすると `start` に保存する（前のタスクの期限は見ない）。`start` を指定したタスクは、前のタスクの期限が動いても動かない。リストの開始日を空にすると、指定を外す（前のタスクから決まる日に戻る）。前のタスクを足しても、開始日は触らない（画面は `addPredecessor`。外すと、利用者が入れた開始日が黙って消えるため。見送った案: 外したうえで通知する）。依頼で期限が指定した開始日より前になるときも、開始日を外して提案の注意に出す（外さないと保存の検査で失敗する）。前のタスクがあり `start` もあるデータは、`start` を使う。同梱のサンプルに該当はない（Excel 取り込みの結果は未確認）。
- 画面では、前後のタスクの確認をしない。期限・開始日の変更（リストの日付欄、ガントのドラッグ、編集の窓）は、そのタスクだけを保存する。次のタスクの期限を超えたときの警告、「前のタスクの期限より前にはできません」のエラー、日程変更の確認パネルは持たない。前後を見て動かすのは、「Claude Code に依頼する」の処理（`core/impact.js`）だけ。画面から期限を変えても、日程変更の履歴（`changeLog`）には残さない（履歴に残るのは、依頼の処理と取り込みの変更だけ）。
- バーにマウスを置くと（`focusDeps`）、そのタスクを青、前のタスクを橙、次のタスクを緑（`--next`）にし、前のタスクとの線を橙、次のタスクとの線を緑にする。ほかは薄くする。線の SVG は、前のタスクの ID を `data-from`、次のタスクの ID を `data-to` に持つ。

- **リストの状態の欄と確認の行**（`views/project.js`・`theme.css`）: リストには「実績」の列を持たない（実績の時間は、稼働・スケジュールで見る）。列の数は見出しの並び（14 列）から数え、全幅の行（区切り行・チェックリストの行・確認の行）の `colspan` に使う。状態の欄の `select` は、最小の幅 `9.5em`（`In Progress`・`Cancelled` が矢印の分を含めて切れない幅）。状態の欄のセルには、`select` と「期限超過」の札だけを出す（`statusCellHtml(t, opts, late, { inline: false })`）。Done・Cancelled の確認（チェックの警告・未来の予定枠の解除）と Waiting の待ち先の入力は、そのタスクの行のすぐ下の全幅の行（`tr.askrow`。中身は `div.askwrap`）に出す。出すのは、`pendingWait` がそのタスクのときと、`pendingDone` がそのタスクで、今日のタスクに入っていないとき（今日のタスクに入っているタスクの Done の確認は、「今日のタスク」の欄に出す）。チェックリストの行も開いているときは、確認の行が先。`div.askwrap` は `position:sticky; left:0` で、幅の上限は、リストの横スクロールの箱（`#view .twrap > .tscroll`。`container-type:inline-size`）の見える幅（`min(60em, 100cqw - 16px)`）なので、リストを右へスクロールしていても、確認が見える範囲に出る。幅 860px 以下（カード表示）では、確認の行もカードの全幅（`grid-column:1/-1`）。ガントの編集の窓・スケジュールの編集欄・今日のタスクの行は、確認を自分の欄の中に出す。
  - 確認したこと（Chromium・Playwright、1400×900、`?today=2026-11-25&time=10:15`、デモデータ（`sample.json` の日付をずらして 2 ファイルに分けたもの）を `showOpenFilePicker` の差し替えで読み込んだ）: 「実績」の列が無いこと。状態の `select` は 124px で、文字が切れないこと。Done にすると、チェックの警告が、そのタスクの行の下の全幅の行に出ること（`colspan` は列数 14 と同じ）。警告の中を押しても閉じず、「やめる」で閉じること。Waiting にすると、待ち先の入力が全幅の行に出て、入力にフォーカスが入り、打てて、「Waiting にする」で、状態と待ち先が入ること。幅 1100px で、リストを右へ 600px スクロールしても、警告の左端が表示領域の左端にあり、ボタンが表示領域の中に入ること。幅 700px（カード表示）でも見えること。未確認: 暗い配色、幅 900px、日本語入力（IME）、タッチ操作、Firefox・Safari での表の中の `position:sticky`、リストの警告が出ているときのガントの編集の窓。

- **チェックリスト**（実装は `core/checklist.js`、編集欄は `views/checklist.js`、編集関数は `edit.js`）。
  - ガント: 項目のあるタスクの行で、左のラベルのタスク名の下に細い線（済みの割合）と「M/N」を出し（`checkMeterHtml`）、バーは左端から M/N に比例した幅を濃く塗る（`.gck`）。バーの右には数字を出さない。`Done`・`Cancelled` のバーには塗りを付けず、点（期限だけのタスク）は塗りなしでラベルだけ出す。全項目が済みのとき、線と数字は緑。項目のないタスクの表示は変わらない。
  - リスト: 「チェック」列に「▸ M/N」（項目なしは「＋ 追加」）。押すと、その行の直後に編集欄の行（`.ck-tr`）が開く。開いているタスクは `S.checkOpen`（メモリのみ、保存しない。ファイルを読み直すと閉じる）。
  - ガントの編集の窓: 「期限」の下・「前のタスク」の上に、同じ編集欄を常に出す。
  - 編集欄: 項目ごとに取っ手（⠿）・チェック・文言・削除、末尾に追加欄。追加は Enter（日本語入力の変換確定の Enter、`isComposing` では追加しない）。文言の編集は `change`（Enter かフォーカスが外れたとき）で保存し、1 文字ごとには保存しない。空にすると「項目を入力してください」で元に戻る。チェック・追加・削除・並び替えは操作のたびに保存する。並び替えは取っ手のドラッグ（同じタスクの中だけ）。項目の `id` は `c<最大番号 + 1>`（削除した番号が末尾なら再利用されうるが、同時に存在する `id` は重複しない。保存の競合で当て直しても結果が同じ）。
  - `Done` にするときの警告（`donecheck.js` の `planDone`、`S.pendingDone` の `stage`）: 未チェックの項目があれば、先にチェックの警告を出し、続けて未来の予定枠の確認（あれば）を出す。チェックの警告は、未完了の項目の一覧と、ヒントの 1 行「不要な項目は、削除してから <状態> にできます。」と、2 つのボタン「残りをすべてチェックして <状態> にする」（`data-ckall`。未来の予定枠があれば、`S.pendingDone` を `stage: "future"`・`checkAll: true` にして確認へ進み、なければ、その場でチェックを付けて Done にする（`setStatus` に `checkAll` の `true` を渡す））と「やめる」（`data-doneno`）だけ。未完了の項目を残したまま Done にする選択肢は持たない（理由は「設計判断」（`design-decisions.md`））。どの段階の「やめる」も、状態も項目も変えない。`Cancelled` など `Done` 以外への変更では、チェックの警告は出ない。リストの選択・ガントの窓・スケジュールの編集欄は、どれも `changeStatus` を通る（今日のタスクには、完了のボタンは無い）。今日のタスクに入っているタスクは、警告が右の列の行に出る（予定枠の確認と同じ）。依頼（inbox）の状態変更は警告しない（変更案を見て承認する流れが確認にあたる）。ToDo タブの完了の入力欄（`completeTask`）は、この警告を出さず、未完了の項目が残ったまま Done で保存しようとするとエラーにする（「ToDo タブ」（`ui-today-todo.md`）の完了の入力欄）。
  - 確認したこと（2 択。Chromium・Playwright、1400×900、`?today=2026-11-25&time=10:15`、デモデータ（`sample.json` の日付をずらして 2 ファイルに分けたもの）を `showOpenFilePicker` の差し替えで読み込んだ）: 今日のタスクの警告（今日のタスクの欄）と、今日でないタスクの警告（リストの行の下）の、どちらも、ボタンが 2 つとヒントの 1 行であること。「残りをすべてチェックして Done にする」で Done・チェック 2/2 になり、警告が消えること。未確認: 「残りをすべてチェック → 未来の枠の確認 → Done」の流れ（実機。`npm test` だけ）、ガントの編集の窓・スケジュールの編集欄での 2 択の見た目。

  - 確認したこと（Chromium・Playwright。ファイル選択は `showOpenFilePicker` を差し替えて開いた）: リストの展開・Enter での追加・変換確定の Enter（`isComposing` を立てた `KeyboardEvent`）で増えないこと・チェック・文言の変更・空文言の差し戻し・削除・ドラッグでの並び替え（合成した `DragEvent`）・ガントの窓との同期。`Done` の警告（リストの選択・今日のタスクのボタン・ガントの窓）の、チェック → 予定枠の順、どの段の「やめる」も不変であること。画面案（Artifact のボード 1〜4）との見比べ（ガントのラベルの線と M/N・バーの塗り・窓の欄の位置・リストの展開・警告の枠・この週のタスク候補の行）。`inbox` は CLI で `propose` → `approve` まで（`tests/inbox-cli.test.js`）、提案のあとに項目が増えると `approve` が失敗すること。
