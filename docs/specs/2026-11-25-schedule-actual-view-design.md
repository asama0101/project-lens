# スケジュールの実績の見せ方と、ToDo タブの今日の ToDo（仕事 3）

## 目的と理由
スケジュール画面で、予定・会議の実績を、「1 つのブロック」として、一目で分かるように見せる。ToDo タブに、スケジュールの内容から決まる「今日の ToDo」を足し、完了の入力欄で、チェックリストを直せるようにする。

理由（利用者の確認の依頼 7 点。画面を実機で見て、次のことが分かった）:
- 予定の枠に実績を入れると、予定のブロックと実績のブロックが並び、2 つに見える。
- 会議は、実績を入れても、ブロックは予定の時刻のままで、文字が付くだけ。会議の実績を消す操作が無い。
- 3 つの状態（開始前・終了後で実績前・終了後で実績後）は、予定の枠では色で分かるが、会議は「実績後」が、予定とほぼ同じ見た目（✓ の文字だけ）。
- 現在時刻の赤い線は、日表示にしか出ない。いまの枠が分かる印も、今日の強調も弱い。
- ToDo タブには、今日の見方が無い。完了の入力欄では、チェックの追加・削除ができない。

## ゴール / 非ゴール / アンチゴール
- ゴール:
  1. 予定の枠・会議が実績を持つとき、実績の時刻に、緑（会議は、実績後と分かる濃い見た目）のブロック 1 つで描く。予定の範囲が実績と違うときだけ、点線の「影」を、予定の時刻に添える。
  2. 予定の枠・会議の、実績の修正と消去ができる（会議の消去を足す）。
  3. 予定の枠・会議の、3 つの状態が、ブロックを分けずに、見た目の違いで分かる。
  4. 現在時刻の赤い線を、週表示の今日の列にも出す。いま進行中のブロックを目立たせる。今日の日付を、いまより強く強調する。
  5. ToDo タブに、左「今日の ToDo」（スケジュールの今日の枠のあるタスク）、右「この週のタスク候補」を並べる。
  6. 完了の入力欄で、チェックリストの項目を、追加・削除できる。
  7. `npm test` が通る。
- 非ゴール: 実績のブロックのドラッグ・伸縮（実績の時刻は入力欄で直す）。1 つの予定に複数の実績の区切り。会議のデータ形式の変更。
- アンチゴール: 稼働・サマリーの数字が変わる（描き方だけを変える）。実績を持たない予定・会議の見た目・ドラッグが変わる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- データ形式は変えない（`sessions[].actual`、`events[].actual`・`confirmed`）。形の正本は `data/sample.json` と `core/schema.js`。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」にそろえる。
- 今日の列には、背景色を付けない（既存の決め。見出しと列の上の線で示す）。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 決めたこと

### カレンダー（週・日表示とも）
- **実績を持つ予定の枠**: 実績の時刻（`actual.date` の列）に、緑のブロック 1 つ（`data-actbar`。ドラッグ・伸縮なし。押すと枠が選ばれる）。文字は「実績 HH:MM-HH:MM ✓」。予定の時刻は、ツールチップ（`title`）と、ブロックが十分高いときの小さな文字で添える。
- **実績を持つ会議**（`actual` あり）: 実績の時刻に、1 つのブロックを描く。実績後と分かる濃い見た目（会議の色の濃いもの。左の実線の縁と ✓）。ドラッグ・伸縮なし。押すと会議が選ばれる。`confirmed: true` で `actual` が無い会議（予定どおり）は、予定の時刻に、実績後の見た目で描く（今までどおり、手動の会議はドラッグできる）。
- **影**: 実績の区間が、予定の区間と、日付または時刻で違うときだけ、予定の時刻（予定の日付の列）に、薄い点線の枠を、実績のブロックのうしろに描く（予定の枠は `data-ghost="<枠の id>"`、会議は `data-mghost="<会議の id>"`）。ドラッグ・伸縮なし。押すと、同じ枠・会議が選ばれる。同じ日で同じ時刻なら、影は描かない。
- **左右に割る描き方は、実績を持つ枠・会議には使わない**。実績を持たない予定の枠と、実績だけの枠・実績のブロックが重なるときの左右割りは、今のまま（影は、重なりの判定に入れない）。
- **予定を動かしたいとき**: 実績を持つ枠・会議は、ドラッグできない。「実績を消す」で、予定の見た目に戻してから動かす（私の判断。実績ができたあとは、予定の時刻を動かす意味がほとんど無いため）。
- **3 つの状態**（枠・会議とも）: 開始前＝予定の色。終了後で実績前＝点線の枠と「未確認」。終了後で実績後＝緑（会議は濃い色）と ✓。ブロックは分けない。凡例の文言を、これに合わせる。
- **会議の実績を消す**: `core/schedule.js` に `clearMeetingActual(data, id)`（`actual` を外し、`confirmed` を `false` にする。会議が無ければ例外）。会議の編集欄に、実績（`confirmed`）があるときだけ「実績を消す」ボタン。消すと、過ぎた会議は未確認、未来の会議は予定の見た目に戻る。
- **現在時刻の線**: 週表示でも、今日の列に、赤い線（日表示と同じ `nowline`）を出す。いま進行中のブロック（描いたブロックの時間に、今が入るもの。参加しない会議を除く）に、強調（赤の外枠と、時刻の前の「いま」の文字）を付ける。
- **今日の強調**: 週表示の日付の見出しの、今日を、塗りつぶし（アクセント色の背景・白い文字）にする。今日の列の上の線を、太くする。日表示の見出しも、今日なら、同じ塗りの印を付ける。

### ToDo タブ
- **2 列**: 左「今日の ToDo」、右「この週のタスク候補」。狭い幅では縦に並べる。
- **今日の ToDo**（`core/week.js` の `todayTasks(data, today)`）: 今日の日付に、予定の枠か、実績の区間（`actual.date`・実績だけの枠）があるタスク（Cancelled を除く）。行に、今日の枠の時刻と札（予定・未確認・実績）を出す。並びは、未完了を、今日の最初の枠の開始順に、完了（Done）を末尾に。表示中の週に関わらず、いつも「今日」を出す。
- **この週のタスク候補**: 今の「この週のタスク」（`weekTasks`）。見出しを「この週のタスク候補」に変える。今日の ToDo と重なるタスクも、そのまま出す（重複してよい）。
- **完了の入力欄**: 左・右とも、同じ行の部品と、同じ入力欄を使う（同時に開くのは 1 行。どちらの列の行かは、どちらでもよい）。
- **チェックリストの追加・削除**: 入力欄の項目の横に「×」、末尾に「＋ 項目を追加（Enter）」。追加・削除は、押したときに、すぐタスクへ保存する（`addChecklistItem`・`removeChecklistItem`。ほかの入力は、下書きに写してから保存し、描き直しても残す）。チェックを付ける・外すと、「残りをすべてチェック」は、今までどおり、「保存」でまとめて書く。この違い（追加・削除はすぐ、チェックは保存のとき）を、`development.md` に書く。

## 作る側に任せること
- ブロックの具体的な色・文字の大きさ・影の透明度・「いま」の印の形。
- 狭いブロックでの文字の出し方（今の `short` クラスの流儀に従う）。
- `todayTasks` の戻り値の細かい形（`weekTasks` の行と同じ項目に、`slots` を足す）。

## 確かめること
- 単体テスト: 実績を持つ枠・会議が、実績の時刻に 1 つだけ描かれる。影が、違うときだけ出る。実績を持たない枠・会議は変わらない。`clearMeetingActual`。週表示に赤い線。進行中のブロックの強調。今日の見出し。`todayTasks`。チェックの追加・削除。
- 既存のテストのうち、2 つ描く前提のもの（`data-dragsess` と `data-actbar` が両方あるなど）を、新しい規則へ直す。
- Playwright（Chromium）で、デモデータを使って、1 回ずつ。確かめていない画面は「未確認」と書く。
