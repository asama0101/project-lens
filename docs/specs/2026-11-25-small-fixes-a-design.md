# 小さな直し 4 件と、チェックの警告の見直し（仕事 5・A）

## 目的と理由
実際に使って出た、画面の使いにくさを直す。

1. リストで、状態の欄が狭く、「In Progress」が切れる。Done にしたときの警告や、Waiting の待ち先の入力が、狭い欄の中で、文字が縦に折れる。
2. リストの「実績」の列は、要らない。
3. 未完了のチェックを残したまま Done にできるが、それが「完了」なのか「チェックし忘れ」なのか、区別がつかない。
4. スケジュールで、予定の枠と会議の、実績の入力欄（ボタンの位置など）が、違う。
5. ToDo タブの「週の見返し」は、稼働タブにあるほうが自然（時間の振り返りの場所のため）。

## ゴール / 非ゴール / アンチゴール
- ゴール: 上の 5 点を直す。`npm test` が通る。
- 非ゴール: タスクの編集の統一（仕事 B）。ToDo タブの催促・今日の優先との連動（仕事 C）。データ形式の変更。
- アンチゴール: 稼働・集計の数字が変わる。「気づき」（`reviews`）が失われる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 決めたこと

### 1. リストの状態の欄・警告（利用者の要望 2）
- 状態の欄に、最小の幅を付けて、「In Progress」「Cancelled」が、切れずに見えるようにする（`select` の文字が全部入る幅）。表が横にあふれるときは、今までどおり、表の中で横にスクロールする。
- Done・Cancelled の確認（未チェックの警告・未来の予定の枠の解除）と、Waiting の待ち先の入力は、リストでは、そのタスクの行のすぐ下に、表の全幅の行（`colspan`）として出す。狭い状態の欄の中には出さない。ガントの編集の窓・今日のタスクの行（幅が十分ある場所）は、今のまま。

### 2. リストの「実績」の列（利用者の要望 4）
- 列と、その見出し・セル・狭い幅の見出し（`data-l="実績"`）を外す。使わなくなる関数・CSS は、外す。実績の時間は、稼働・スケジュール・ガントの実績の線で見られる。

### 3. チェックの警告（利用者の要望 3）
- Done にするとき、未完了の項目があれば、警告は 2 択にする: 「残りをすべてチェックして Done にする」「やめる」。「未完了のまま Done にする」は、なくす。不要な項目は、削除してから Done にする。
- Cancelled には、チェックの警告は出ない（今のまま）。未来の予定の枠の解除の確認は、今のまま。

### 4. 予定の枠と会議の、実績の入力欄をそろえる（利用者の要望 9）
- 予定の枠を選んだときの実績の欄と、会議を選んだときの実績の欄を、同じ部品・同じ場所・同じ並びにする: 編集の領域（`#mtgslot`）の先頭に「実績」の欄を出す。並びは「実績」のラベル・日付・開始・終了・ボタン（「実績を保存」か「実績を更新」、あれば「実績を消す」）。ボタンは、同じ行の右端に、同じ順で並べる。
- 会議の日付は、会議の日付で固定（変えられない）なので、日付は文字で出す。枠の実績の日付は、今までどおり、直せる。
- 会議の、件名・日付・時刻・プロジェクト・参加しない、の編集の欄は、その下に出す（今の、実績の欄が、その欄の一部だった形をやめる）。
- 保存・消去の動き、下書き（`S.actDraft`）、「始まっていない枠・会議には出さない」の規則は、今のまま。

### 5. 週の見返しを稼働タブへ（利用者の要望 12）
- ToDo タブから、「週の見返し」の領域を外す。稼働タブの下に、「週の見返し（M/D〜M/D）」を出す。内容は、今のまま（完了 X / Y 件・予定と実績の分・タスクごとの表・気づきの欄）。
- どの週か: 稼働タブで見ている日（`S.wdate`）を含む週。稼働の期間（日・週・月）が何であっても、その日を含む週。稼働の日・週の移動（← →・今日）に従う。
- 気づき（`reviews`）の保存は、今のまま（欄を離れたとき。個人ファイル）。ToDo タブの週の移動は、「この週のタスク候補」のためだけに残る。
- 週の見返しの描画（`weekSummary` を使う部分）は、`views/workload.js` に置く（`views/todo.js` から移す）。

## 作る側に任せること
- 最小の幅の具体的な値。実績の欄の、細かい見た目（既存の `.actform` の流儀に合わせる）。

## 確かめること
- 単体テスト: 実績の列が無い。ask の行が、`pendingDone`・`pendingWait` のとき、表の全幅の行として出る。警告が 2 択（`data-ckkeep` が無い）。会議と枠の実績の欄が、同じ並び・同じ位置。稼働タブに週の見返しが出て、ToDo タブには出ない。選んだ日を含む週になる。
- 既存のテストのうち、これらを前提にするものを、新しい規則へ直す（弱めない）。
- Playwright（Chromium）で、デモデータを使って、1 回ずつ。確かめていない画面は「未確認」と書く。
