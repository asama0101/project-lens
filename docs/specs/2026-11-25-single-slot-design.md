# 予定と実績を、1 つの作業枠に持たせる（仕事 1）

## 目的と理由
作業枠の「予定」と「実績」を、別々の枠ではなく、1 つの枠に持たせる。実績の時刻を、あとから直せるようにし、直した結果が、カレンダー・ガントチャート・稼働に、そのまま反映されるようにする。

理由:
- 今は、実績が、予定とは別の枠（`kind: "actual"`）。実績を直す手段が、ドラッグだけで、予定の枠から「実績を保存」し直すと、実績どうしの重なりでエラーになる。「実績を更新して時間を変える」ができない。
- ガントの実績の線は、日付だけを使い、時間を持たない。
- 予定と実績が、画面の上で別々の 2 つの枠になり、対応が分かりにくい。

続く仕事 2（ToDo タブを、プロジェクトのタスクを元に作り直す）が、この枠の上に乗る。

## ゴール / 非ゴール / アンチゴール
- ゴール:
  - 予定の枠に、実績（日付・開始・終了）を持たせられる。保存し直すと、更新される。消すこともできる。
  - 実績を更新すると、カレンダー・ガントの実績の線・稼働・サマリーの実績の時間・「今日のタスク」の札が、すぐに変わる。
  - 予定の無い作業は、これまでどおり「実績だけの枠」で入れられる。
  - `npm test` が通る。
- 非ゴール:
  - ToDo タブの作り直し（仕事 2）。
  - 実績の帯を、カレンダー上でドラッグして動かす・伸ばす（実績の時刻は、入力欄で直す）。
  - 1 つの予定に、複数の実績の区切りを持たせること（区切って作業したときは、「実績だけの枠」を足す）。
- アンチゴール:
  - すでに実績の作業枠と、確認済みの会議の、稼働の数字が変わる。
  - 実績の時間が、稼働に二重に数えられる（予定の枠の実績と、同じ時間の実績だけの枠）。
  - 今の形（予定の枠と、別の実績の枠）のデータが、読めなくなる・数字が変わる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- データ形式の正本は、`data/sample.json` と `src/core/schema.js`。形を変えたら、両方を直す。
- 「旧形式の移行・読み替えは持たない」。ただし、今の形（予定の枠と、別の実績の枠）は、そのまま読めて、同じ数字になる（下の「今の形の扱い」）。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープする。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も、同じ作業で直す。

## 案の比較
| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| 1（採用） | 予定の枠に、任意の `actual`（日付・開始・終了）を持たせる | 1 つの枠で、予定と実績の対応が明らか。上書きで更新できる。保存先が変わらない（個人ファイルの枠の中） | 枠を読む箇所を、「実績の区間」を通す形に直す |
| 2 | 実績の枠に、元の予定への参照（`plannedId`）を持たせる | 枠は別々のまま | 参照の整合（予定を消す・動かす）の規則が増える。「更新」は、結局、参照先の実績を探して直す |
| 3 | 今のまま、実績を直す欄だけを足す | 変更が小さい | 予定と実績が別々の枠のまま。ガントの線・対応の分かりにくさは残る |

## 決めたこと

### データ
- 作業枠は、今のまま `{ id, date, start, end, kind }`。`kind: "planned"` の枠だけが、任意の項目 `actual: { date, start, end }` を持てる。`date` は、いつも書く（予定の枠を別の日へ動かしても、実績の日は動かないため）。
- `kind: "actual"` の枠（実績だけの枠）は、今のまま。予定の無い作業と、区切って作業した分に使う。
- **実績の区間**: 実績の作業枠の自身の時間（`kind: "actual"`）と、予定の枠の `actual`。稼働・ガントの線・実績の時間の集計は、すべて、この区間を通して数える。1 つの区間は、1 回だけ数える。

### 規則
- 実績の区間どうしは、重ならない（タスクと ToDo をまたいで判定する。今の「実績の枠どうしは重ならない」と同じ）。`validate` で、`actual` の形（日付・時刻・終了が開始より後）と、区間の重なりを検査する（今の重さのまま `err`）。`kind: "actual"` の枠に `actual` を持たせるのは `err`。
- 保存の操作では、実績の開始が今より後のものを受けない（終了は、今より後でもよい）。休みの日にも置ける（今のまま）。最短は 15 分。
- **未確認**: 過ぎた予定の枠（終了が今以前）で、`actual` が無く、重なる実績の区間も無いもの（今の規則に、「自分の `actual` が無い」を足したもの。今の形のデータが、そのまま同じ判定になる）。
- 予定の枠の状態の判定（`sessionKind`）: `actual` を持つ予定の枠は `actual`（実績あり）。画面の札・稼働の集計は、枠の状態ではなく、実績の区間で数える。サマリーの「予定 N 件」は、実績の無い予定の枠の数。
- タスクが To Do・Waiting のとき、実績を保存すると In Progress にする（今のまま。Waiting の待ち先は外れる。ToDo は状態の変更なし）。

### 操作（スケジュール画面）
- 予定の枠を選ぶと（開始が今以前のもの）、実績の入力欄が出る: 日付・開始・終了（すでに実績があればその値、なければ予定の時刻が初期値）。ボタンは「実績を保存」（実績があるときの文言は「実績を更新」）と、実績があるときの「実績を消す」。
- 「実績を保存」は、その予定の枠の `actual` を書く（上書き）。タスクの状態の自動変更と、重なり・開始の検査は、上の規則に従う。
- 「実績を消す」は、`actual` だけを外す（予定の枠は残る）。
- 枠を削除すると、予定と実績の両方が消える。`actual` があるときは、削除の前に確認を出す（「実績 N 分も消えます」。ToDo の削除と同じ流儀）。
- 「＋ 実績を追加」（予定の無い作業）は、今のまま、実績だけの枠を足す。

### 画面
- 予定の枠が `actual` を持つとき、カレンダーには、予定のブロックと、実績の帯を、並べて描く（実績の帯は、その日付の列の、実績の時刻の位置に置く。予定と時間が重なるときは、予定を左半分、実績を右半分に並べる。今の「予定と実績の枠を並べる」描き方と同じ）。どちらを押しても、同じ枠が選ばれる。実績の帯は、ドラッグできない。
- ブロックの文字: 予定の時刻（予定のブロック）、実績の時刻と ✓（実績の帯）。実績だけの枠は、今のまま。
- ガントの実績の線: 最初の実績の区間の日付から、完了日（未完了なら今日）まで（区間の日付は、`actual.date` か、実績だけの枠の `date`）。
- 稼働: 実績の区間の時間を、区間の日付で、プロジェクト別に数える。サマリー「実績 N 時間」も、表示中の期間の実績の区間の合計。
- 「今日のタスク」「今日の ToDo」の札: 予定の枠が `actual` を持つとき、「実績」の札と、実績の時間を出す（予定の時間は添える）。

### 今の形の扱い
- 予定の枠と、別の実績の枠が並んでいるデータは、そのまま読む。数字（稼働・ガントの線・未確認の判定）は、今と同じ。予定の枠の `actual` が無く、重なる実績の枠があれば、未確認でない（今の規則）。
- 今の形の予定の枠に、新しく実績を保存するとき、同じ時間の実績の枠と重なれば、重なりのエラー（先に実績の枠を消す）。自動での統合はしない（時間が違う複数の実績を、勝手に 1 つにしないため）。

### 検証・データ
- `validate`: `actual` の形、`kind: "actual"` の枠の `actual`、実績の区間の重なり。
- `sample.json`: 実績を持つ予定の枠を 1 件足す（今の形の例も残す）。

### 細部の判断（すべて私の判断。実装者の確認で出た質問への答え）
- 予定の時間は、`kind: "planned"` の枠の自身の時間（開始〜終了）の合計。`actual` を持っていても、持っていなくても、数える（今の形で、実績の枠が足されても予定の枠が残る数え方と同じ）。稼働画面は、今までどおり、実績の区間だけを数える（予定の時間は出さない）。ToDo の予定・実績の分数（`todoMinutes` など）は、予定の枠の自身の時間と、実績の区間で数える。
- 会議の実績（`actual`・`confirmed`）は、「実績の区間」に含めない。会議との重なりは、今のまま警告だけで、稼働は重なりを除かない。
- 実績の区間の重なりは、`kind: "actual"` の枠と、予定の枠の `actual` を合わせて `err`（今のデータでは、予定の枠に `actual` は無いので、読めなくなるデータは出ない。手で編集して重ねたときは、`validate` が `err` にする）。
- `actual.date` は、予定の枠の日付と別の日でもよい。カレンダーは、予定の枠の日付が表示範囲外でも、`actual.date` が範囲内なら、その日の列に実績の帯を描く（予定のブロックは、予定の日付が範囲内のときだけ）。サマリー・稼働は、実績の区間の日付で範囲を絞る。実績の帯を押すと、その枠が選ばれる（選んだ枠の入力欄は、予定の枠が表示範囲外でも出る）。
- 実績の入力欄は、予定の枠の開始が今以前のとき、または、その枠がすでに `actual` を持つときに出す（`actual` を持つ枠を、あとから未来の予定へ動かしても、実績を更新・消せる）。予定の枠を動かしても、`actual` は動かさない。実績の保存の検査（開始が今より後は不可など）は、保存のときだけ行う。

## 作る側に任せること
- 実績の区間を通す、共通の読み取りの関数の名前と置き場所（`core/sessions.js`）。
- カレンダーの実績の帯の見た目（色・文字・幅）、狭いブロックでの文字の出し方。
- `todos.js` の `todoMinutes`・`weekReview`・`carryTodo`（実績のある予定の枠は、回すとき消さない）の、実績の区間への直し。

## 確かめること
- 単体テスト: 実績の保存・更新・消去（`actual` が書き換わる、予定の枠は残る）。実績の区間どうしの重なり（実績だけの枠との重なりを含む）。開始が今より後はエラー。未確認の判定（`actual` を持つ枠は外れる、持たない過ぎた予定は未確認）。稼働・ガントの線・サマリーが、実績を直すと変わる。今の形のデータの数字が変わらない。予定の枠を別の日へ動かしても、実績の日は動かない。削除の確認（`actual` があるとき）。
- 既存のテストのうち、実績の枠を前提にするものを、新しい規則に直す。
- Playwright（Chromium）で、予定の枠 → 実績を保存 → 時刻を直して更新 → カレンダー・ガント・稼働に反映、実績を消す、削除の確認を、1 回ずつ。確かめていない画面は「未確認」と書く。

## 次の仕事（仕事 2）に、この仕事が渡すもの
- タスクと、その予定・実績の区間。ToDo タブを、タスクを元にした「今週の見方」に作り直す。完了の入力欄（実績・状態・チェックリスト）は、この仕事の「実績を保存」を使う。
