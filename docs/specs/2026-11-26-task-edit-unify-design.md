# タスクの編集の統一（仕事 B）

## 目的と理由
タブごとに、タスクの見える項目・直せる項目が違う。

1. ガントの編集の窓に、待ち先・回答予定日が出ない（直せない）。
2. ガントのバーに、待ち先・回答予定日が出ない。
3. リストから、繰り返しを指定できない。
4. 編集の項目を出す部品が、窓とスケジュールで別々で、項目を足すと出し忘れが起きる。

## ゴール / 非ゴール / アンチゴール
- ゴール: ガントの窓・スケジュールの編集欄・リストで、同じ項目が見えて直せる。Waiting のバーに待ち先・回答予定日が出る。`npm test` が通る。
- 非ゴール: 今日のタスク・ToDo タブの編集（仕事 C）。データ形式の変更。見た目の全面的な作り直し。
- アンチゴール: 優先の点数・稼働の数字が変わる。入力途中の文字が、描き直しで消える。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- 画面に ID を出さない（ガントの窓・リストの既存の ID 表示は、今のまま）。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」。
- PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 決めたこと（利用者の承認済み。画面案: https://claude.ai/artifact/G4MntmgnSrzjiJog5zYLm8）

### 1. 編集の項目を、1 つの部品にそろえる
- 窓（`taskFieldsHtml`）とスケジュール（`taskRowFieldsHtml`）の、項目ごとの HTML を共通の関数（`views/taskpop.js`）にする。並べ方（縦／折り返しの横並び）は、場所ごとに今のまま。
- 項目: 件名・プロジェクト・状態・開始・期限・重要・メモ・待ち先・回答予定日・繰り返し・前のタスク・チェックリスト。
- 3 か所（ガントの窓・スケジュール・リスト）で、同じ項目が見え、同じ `data-f`・`data-id` の属性で直せる（保存は、既存の `change` の結線が、`data-f` で受ける）。

### 2. 待ち先・回答予定日
- ガントの窓とスケジュールの編集欄に、「待ち先」「回答予定日」の欄を、状態の次に足す。状態が Waiting のときだけ出す（それ以外は欄を出さない）。入力の属性は、リストと同じ（`data-f="party"`・`data-f="expected"`）。待ち先が空のあいだ、回答予定日は無効（リストと同じ）。
- 状態を Waiting にするときの待ち先の入力（`pendingWait`）は、今のまま。

### 3. ガントのバー（案 1）
- Waiting のタスクだけ。回答予定日があれば、その日の位置に ◆ を置く。バーの右に、「待ち: 待ち先 ・ M/D」を文字で出す。回答予定日がなければ、◆ は出さず、「待ち: 待ち先」だけ。待ち先が空なら、何も足さない。
- 回答予定日が今日より前（過ぎている）なら、◆ と文字を赤にし、文字に「超過」を足す。
- 文字がレーンの右端からはみ出す位置になるときは、バーの左に出す。◆ と文字は、クリック・ドラッグを邪魔しない（バーの操作は、今のまま）。
- ◆ の位置は、バーの外（開始より前・期限より後）でも、表示の範囲内なら出す。範囲外なら出さない。

### 4. リストの繰り返し
- 列は増やさない。行のチェックの欄の隣に「詳細」のボタンを置き、押すと、行の下に「詳細」の行（`tr.ck-tr` と同じ流儀の全幅の行）を開く。中身は、繰り返しの選択（なし／毎週／毎月）と、説明の 1 行。
- 開いている行の状態は、`S.detailOpen`（`Set`）。チェックリストの行の開閉（`S.checkOpen`）とは別。画面を移ると閉じる。
- 繰り返しのあるタスクの ↻ の表示は、今のまま。

## 作る側に任せること
- ◆ と文字の細かい見た目（色・大きさ。既存のバー・`--late` の色に合わせる）。「詳細」の行の細かい見た目。

## 見送った案
- ガントのバーを ◆ だけにする: 誰を待っているかが、窓を開かないと分からない。
- リストに繰り返しの列を足す: 行が既に 14 列で、横に広がりすぎる。

## 確かめること
- 単体テスト: 3 か所で、同じ項目の入力（`data-f`）が出る。Waiting のときだけ待ち先・回答予定日の欄が出る。バーの ◆ と文字（回答予定日の有無・超過・待ち先が空）。リストの「詳細」の開閉と繰り返しの保存。ID が、新しい表示に出ない。
- Playwright（Chromium）、デモデータで、ガントの窓・バー・リストの詳細・スケジュールの編集欄を、1 回ずつ。確かめていない画面は「未確認」と書く。
