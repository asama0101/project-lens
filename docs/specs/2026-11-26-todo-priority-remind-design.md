# ToDo タブと今日の優先の連動、Waiting の催促（仕事 C）

## 目的と理由
1. 「この週のタスク候補」の並びが、「今日の優先」の並びと関係なく、どれから手を付けるかが分からない。
2. 「今日の優先」で選んだタスクを、ToDo タブへ移らずに、今日の予定へ入れられない。
3. Waiting のタスクは、回答予定日を過ぎても、気づかないと催促を忘れる。催促したことを、記録して、次の催促の日を決めたい。

## ゴール / 非ゴール / アンチゴール
- ゴール: 候補が優先の順に並び、理由が出る。「今日の優先」の行から「今日へ」できる。ToDo タブに「催促」の組が出て、「催促した」で次の回答予定日まで決められる。`npm test` が通る。
- 非ゴール: 優先の点数の変更。Waiting の自動の通知（メール・外部への送信）。催促の履歴の保存。
- アンチゴール: 今日の優先の順位・点数が変わる。入力途中の文字が、描き直しで消える。データ形式が変わる（使うのは、既存の `waitingOn.{party, since, expected}` と `settings.waitingLongDays`）。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」。純関数・不変更新。
- PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 決めたこと（画面案の承認済み: https://claude.ai/artifact/VTU9T4tDqQJsd4jhaQMBQF の案 1。上下は、今日の ToDo が上、催促が下）

### 1. 候補を優先の順に並べ、理由を添える
- 「この週のタスク候補」の未完了の行（期限超過・今週に予定あり・今週の期限）を、1 つの並びにまとめ、`rankTasks`（今日の優先の順）の順に並べる。見ている週が今週でなくても、今日を基準にした点数の順。
- 各行の下の 1 行に、`rankTasks` の理由を「・」でつなぐ（期限超過 N日・重要・前のタスク待ち・次のタスク N 件を止めている など）。予定の枠が今週にあるタスクは、先頭に「今週に予定あり」を足す。
- 完了（Done）の組は、今までどおり、末尾の「完了」の組。見出しは、未完了の並びには付けない。
- 「完了」「今日へ」・ドラッグ・入力欄の動きは、今のまま。

### 2. 「今日の優先」の行に「今日へ」
- 「今日の優先」（ガント・リスト・スケジュール）の、未完了の行に「今日へ」を出す。押すと、ToDo タブへ移り、見る週を今週にして、そのタスクの「今日へ」の入力欄（`S.tdPlan`）を開く（`openPlan` を使う）。
- スケジュール画面では、すでにドラッグで今日の枠へ入れられるので、「今日へ」は出さない（ガント・リストだけ）。

### 3. 催促（Waiting）
- 左の列の「今日の ToDo」の下に、「催促（N 件）」の組を出す。0 件なら、組ごと出さない。
- 入れるタスク: 状態が Waiting で、次のどちらか。
  - 回答予定日（`waitingOn.expected`）が、今日より前。
  - 回答予定日が無く、待ち始め（`waitingOn.since`）から、`settings.waitingLongDays` 日以上。待ち始めが無いときは入れない。
- 回答予定日が、今日以降のものは、入れない（待ち始めが長くても）。
- 並び: 予定日を過ぎた日数が多い順 → 回答予定日の無いもので待った日数が多い順（同じなら、件名の ID の順）。
- 行: プロジェクト名・件名・「待ち先: ○○ ・ 回答予定 M/D（N 日超過）」または「待ち先: ○○ ・ 回答待ち N 日」。待ち先が空なら「待ち先: 未設定」。ボタン「催促した」「待ち先・予定日を直す」。
- 「催促した」: 行の下に入力欄を開く。「次の回答予定日」は、今日から 1・2・3・5・7 日後の選択（初期は 3 日後）。「記録する」で、待ち始め（`since`）を今日、回答予定日を今日 + N 日にして保存する（待ち先は変えない）。「キャンセル」で閉じる。保存すると、その行は催促から消える。
- 「待ち先・予定日を直す」: 行の下に、待ち先の文字欄と回答予定日の日付欄を開く（今の値が入る）。「保存」で、待ち先と回答予定日を更新する（`since` は、そのまま）。回答予定日を空にして保存すると、予定日を外す。待ち先を空にして保存することは、できない（通知で断る。入力は残る）。
- 状態の動き: 左の列の他の入力欄（完了・今日へ・突発）と、同時に 2 つ以上は開かない。画面の移動・週の移動・描き直しの検証（タスクが無い・Waiting でなくなった）で閉じる。失敗したら、通知だけで、入力欄と入力は残る。
- 純関数: `chaseTasks(data, today)`（`core/week.js`）、`markChased(data, taskId, days, today)`（`ui/edit.js`。Waiting 以外・待ち先が空・`days` が 1〜30 の整数でないとき、エラー）。

## 作る側に任せること
- 理由の行・催促の組の細かい見た目（既存の `.td-row`・`.actform` に合わせる）。「今日の優先」の「今日へ」の置き場所の細部。

## 見送った案
- 催促の組を、「今日の ToDo」の上に置く: 利用者が、下に置くと決めた。
- 催促を、点数に足す（今日の優先に入れる）: 今日の優先の点数は、変えない（非ゴール）。回答予定日を過ぎたときの +40 は、すでにある。
- 催促の履歴を持つ: データ形式の変更になり、使い道が決まっていない。

## 確かめること
- 単体テスト: `chaseTasks`（予定日の前後・当日・予定日なしで日数の境界・待ち始めなし・Waiting 以外・並び）。`markChased`（since・expected・エラー）。候補の並びが rank の順で、理由が出る。「今日の優先」の「今日へ」（ガント・リストに出る、スケジュールに出ない）。催促の組・入力欄の出入り・失敗で入力が残る。ID が画面に出ない。
- Playwright（Chromium）、デモデータで、ToDo タブの並び・催促・今日の優先の「今日へ」を、1 回ずつ。確かめていない画面は「未確認」と書く。
