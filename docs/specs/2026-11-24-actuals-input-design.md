# 実績の入れ方の作り直し（仕事 1）

## 目的と理由
「実績にする」ボタンを廃止し、スケジュール画面から、予定とは別の枠として実績（作業枠・会議）を入れられるようにする。

理由は 2 つ。
- 今の「実績にする」は、予定の枠の種別を書き換えるだけで、予定と実績のずれが残らない。改善活動（予定どおりにできたか、どこでずれたか）の材料にならない。
- 続く仕事 2（日・週の ToDo タブ）が、「使った時間」を、この実績の枠の合計で持つ。実績の入れ方を先に作り直しておく。

## ゴール / 非ゴール / アンチゴール
- ゴール: 下の「決めたこと」がすべて動き、`npm test` が通る。予定の枠を選び、保存を 1 回押すだけで、予定どおりの実績が入る。
- 非ゴール: ToDo タブ（仕事 2）、開始・停止のタイマー、他の人の実績の表示。
- アンチゴール:
  - すでに実績の作業枠と、確認済みの会議の、稼働の数字が変わる。
  - 実績の作業枠どうしが重なり、同じ時間が稼働に二重に数えられる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- データ形式の正本は、`data/sample.json` と `src/core/schema.js`。形を変えたら、両方を直す。
- 「旧形式の移行・読み替えは持たない」が既存の方針。ただし、すでに `confirmed: true` の会議は、稼働の履歴なので、読み替えて残す（下の「会議」）。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`docs/guide.md`・`README.md` の画面の説明（「実績にする」「未確認」）も、同じ作業で直す。

## 案の比較
| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| X（採用） | 実績を、予定とは別の枠として入れる | 予定と実績のずれが見える | 重なりの規則と、会議の持ち方を変える |
| Y | 予定の枠を、直接、実績に書き換える | 枠は 1 つで操作が短い | ずれが残らない（今と同じ） |
| 先に ToDo だけ | 今のボタンを残す | 変更が小さい | 実績が 2 通りになる。ToDo の時間が不正確になる |

## 決めたこと

### 作業枠
- 枠の種別は、今のまま `planned`・`actual`。実績の枠は、予定の枠と**重なって置ける**。置けないのは、実績どうしの重なりだけ（予定どうしの重なりも今のまま置けない）。
- 実績を入れる操作は 2 つ。
  1. 週表示・日表示で予定の枠を選ぶと、編集欄に「実績」の開始・終了が、予定の時刻で入っている。時刻を直して「保存」を 1 回押すと、実績の枠ができる。予定の枠は残る。
  2. 「実績を追加」（タスク・日付・開始・終了）。予定のない作業を入れる。（私の判断。予定なしでやった作業を入れる口が要るため）
- 実績の枠は、選んで時刻を直す・消すことができる。開始が今より後の実績は置けない（終了は今より後でもよい）。（私の判断。今の「明日以降の枠は実績にできない」を引き継ぐ）
- 実績の枠を未来へ動かしたときに、予定へ戻す今の規則は廃止する。実績が未来へ動く操作は、エラーにする。（私の判断）
- 実績を保存したとき、タスクが To Do・Waiting なら、In Progress にする。今日のタスクの「実績にする」の規則を引き継ぐ。Waiting の待ち先は外れる。（私の判断）
- 廃止するもの: 「実績にする」「未確認をすべて実績にする」のボタンだけ。
- 残すもの: 「未確認」の状態。意味は「予定の時間が過ぎたのに、実績が未入力」。札・橙の点線・凡例・稼働画面の「未確認 N 件」の案内は、今のまま出す。
- 作業枠の未確認は、過ぎた予定の枠で、時間が重なる実績の枠が 1 つも無いもの。実績の枠を入れると消える。予定の枠は、実績ができても消えない。
- 未確認の範囲を区切る設定は持たない。導入前の過去の会議が未確認で埋まらないよう、予定表から取り込む会議を、日付が今日以降のものだけにする（次の「取り込み」）。すでにデータにある古い未確認の枠・会議は、手で消す。多すぎて困ったときに、区切る設定を足す（見送った案）。

### 取り込み
- 予定表の取り込み（`calendar-auto`・`calendar-apply`、`skills/intake` の予定表の取得）は、日付が今日より前の会議を落とす。依頼で期間の開始を過去にしても、同じ。当日の、すでに終わった会議は取り込む。
- 既定の期間（今日から 14 日後まで）は、変えない。会議は先に取り込まれるので、同期しなかった日の会議も、たいてい取り込み済み。
- 取り込み済みで、あとから過ぎた会議は、今の規則どおり残り、実績を入れるまで未確認として出る。

### 会議
- `confirmed: true` の意味は、「参加した」。実績の時間は、新しい任意の項目 `actual: { start, end }` で持つ。`actual` が無く `confirmed: true` なら、予定の時刻を実績とみなす（既存データを変えない読み替え）。（私の判断。履歴を移行せずに残すため）
- 会議を選ぶと、編集欄に実績の開始・終了が予定の時刻で入っている。「保存」で、`confirmed: true` と `actual` を書く。
- 出なかったときは、今のとおり「参加しない」（`skip: true`）。
- 会議の日時を動かしたとき、`confirmed` と `actual` を外す（今の規則を `actual` にも広げる）。
- 稼働は、`confirmed` の会議を、`actual` の時間（無ければ予定の時間）で数える。

### 検証・データ
- `validate` に、会議の `actual`（時刻の形式、開始が終了より前）と、実績の枠どうしの重なり（warning）を足す。
- `sample.json` に、予定と違う時刻の実績を持つ会議を 1 件足す。

### 細部の判断（すべて私の判断。実装者の確認で出た質問への答え）
- 実績の作業枠と、会議の実績の時間が重なる場合は、今の規則どおり、保存を止めず警告だけにする。稼働は重なりを除かない。
- 実績の枠は、元の予定の枠への参照を持たない。同じ予定から実績を 2 回保存しようとして、時間が重なれば、実績どうしの重なりでエラーになる。予定との対応は、同じ日に予定と実績が並んで見えることで示す。
- 状態の判定は、作業枠が `planned`・`actual`・`unconfirmed`、会議が `planned`・`actual`・`unconfirmed`・`skipped`（今と同じ）。作業枠の `unconfirmed` は、上の規則（過ぎた予定で、重なる実績が無い）で決める。会議の `unconfirmed` は、`skip` も `confirmed` も無い過ぎた会議（今と同じ）。`unconfirmed` は、稼働に数えない（今と同じ）。
- 「開始が今より後の実績は置けない」は、保存の操作でだけ確かめる。`validate`（読み込み）では確かめない。すでに開始が未来の実績が残っているデータも、そのまま読み込める。
- `actual` の無い `confirmed: true` の会議を動かしたときも、今の規則どおり、`confirmed` を外す（今と同じ。履歴は、動かす前の日付の稼働からは消えるが、動かすのは利用者の操作）。
- `taskActual`・`metrics.js` の `actualSpan`・進捗や日程変更の算出は変えない。実績だけを入れた作業（予定の無い作業）も、今の実績の枠と同じに扱う。
- 「実績を追加」の候補は、Done・Cancelled 以外のタスク。状態を In Progress にする規則は作業枠の実績だけで、会議には当たらない。実績を消しても、状態は元に戻さない。
- `docs/flow.html` は、`skills/`・`agents/`・`tools/` の手順と分岐を変えたときだけ直す。`intake-calendar.md` の言葉だけを直す場合は、直さない。

## 作る側に任せること
- 編集欄の見た目、会議の実績が予定とずれたときの表示の方法（予定と実績の違いが、一目で分かること）。
- 過ぎた予定の枠の薄さ・色。
- `tools/`（`cli.js` ほか）、`agents/intake-calendar.md` の「未確認の会議」の言葉が、新しい仕組みと合っているかの確認と直し。

## 確かめること
- 単体テスト: 未確認の判定（実績の枠が重なれば外れる）、取り込みが今日より前の会議を落とすこと（当日の終わった会議は取り込む）、実績と予定の重なり（置ける）、実績どうしの重なり（置けない）、開始が未来の実績（置けない）、会議の `actual` の保存・日時変更での解除、稼働が `actual` の時間で数えること、`confirmed: true` だけの会議が予定の時間で数えられること。
- 既存のテスト（`sessions.test.js`・`schedule.test.js`・`edit.test.js`・`calendar.test.js`）のうち、「未確認」や `confirmSession` に依存するものを、新しい規則に直す。
- Playwright（Chromium）で、予定の枠 → 保存 1 回、時刻を直して保存、会議の実績、実績の削除を 1 回ずつ実行する。確かめていない画面は「未確認」と書く。

## 次の仕事（仕事 2）に、この仕事が渡すもの
- ToDo の「使った時間」は、実績の枠（`taskId` で ToDo を指す）の合計になる。予定の時間は、予定の枠の合計。
