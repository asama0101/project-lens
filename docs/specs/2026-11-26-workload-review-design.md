# 稼働タブの見返しの見直し（仕事 E）

## 目的と理由
稼働タブの下の「週の見返し」は、稼働の期間（日・週・月）によらず、いつも「その日を含む週」を出す。気づきの欄は使われない。プロジェクトごとの進捗が見えず、タスクの表にも、どのプロジェクトか出ない。

## ゴール / 非ゴール / アンチゴール
- ゴール: 稼働の期間（日・週・月）に合わせて、タスクの集計の範囲が切り替わる。プロジェクト別の表に、完了と進捗が加わる。タスクの表に、プロジェクトの列が出る。気づきの欄を、なくす。`npm test` が通る。
- 非ゴール: 稼働の時間の集計（`workload`）の変更。ToDo タブの候補（`weekTasks`）の動きの変更。気づきの代わりの機能。
- アンチゴール: 稼働の数字（時間）が変わる。ToDo タブの候補の並び・組が変わる。個人ファイルの `reviews`（過去の気づき）が、保存で消える。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」。純関数・不変更新。
- PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 決めたこと（画面案: https://claude.ai/artifact/LV1pp1rTf5WyeLegTbeUgm。利用者が、案 A（プロジェクトの列）を選び、見返しの文言は不要、プロジェクト別は今のタスクと会議の内訳を残す、と指示）

### 1. 画面の形
- 稼働タブは、(a) 期間の操作とプロジェクト別の表（今の「稼働」の領域）、(b) その下の「タスク」の表、の 2 つ。「見返し」という見出しと、「完了 X / Y 件　予定…に対して実績…」の文は、なくす。「気づき」の欄も、なくす。
- (a) プロジェクト別の表: 今の列（プロジェクト・タスク・会議・合計・内訳の棒）を残し、右に「完了」（`n / m 件`、0 件のとき `—`）と「進捗」（完了の割合の棒）を足す。末尾の合計の行にも、完了の合計を出す。「プロジェクト未設定」の行にも、同じ列を出す。
- (b) 「タスク」の表: 列は「プロジェクト」「タスク」「進捗」「予定」「実績」。プロジェクトは、名前（プロジェクト未設定は「プロジェクトなし」）。並びは、今までどおり（期限超過 → 予定あり → 期限 → 完了、同じ組の中は期限・ID の順）。0 件なら、表を出さず「この期間のタスクはありません。」。見出しは「タスク」。

### 2. 期間に従う
- 集計の範囲は、稼働の期間（`periodRange(period, date)`。日は、その日、週は、その日を含む週、月は、その月）。←→・今日・日／週／月の切り替えに従う。
- タスクの対象と組は、今の `weekTasks` の規則を、週から任意の範囲 `[start, end]` に広げたもの: Cancelled は除く。Done は、完了日（`doneAt`）が範囲にあるか、範囲に予定の枠か実績がある。未完了は、期限が今日より前なら「期限超過」、範囲に予定の枠か実績があれば「予定あり」、期限が範囲の終わり以前なら「期限」。
- 純関数 `rangeTasks(data, range, today)`（`core/week.js`）を足し、`weekTasks(data, weekStart, today)` は、週の範囲で `rangeTasks` を呼ぶだけにする（ToDo タブの動きは変えない）。
- 純関数 `projectProgress(rows)`（または同等。置き場所は作る側）: 行を、プロジェクトの ID ごとに `{ done, total, ratio }` にまとめる（Done の件数 / 行の件数）。

### 3. 気づきをなくす
- 画面（欄・`data-tdnote`・`.tdreview` の CSS）と、保存の結線（`app.js` の `tdnote` の処理・`focusSelector` の `tdnote`）、`setReview`、`weekSummary` を消す。`reviews` を使うテストは、新しい規則へ直す（弱めない）。
- 個人ファイルの `reviews`（過去の気づき）は、そのまま残す: `splitData`・`mergeData`・スキーマの `reviews` の扱いは変えない（読んで、そのまま書き戻す）。画面には出ない。

## 作る側に任せること
- 完了の割合の棒・「完了」の列の細かい見た目（既存の `.wl-bar`・`.bar` 系に合わせる）。タスクの表のプロジェクト名の見た目。

## 見送った案
- タスクの表を、プロジェクトの見出しでまとめる（案 B）: 期限超過の順など、今の並びが崩れる。
- ファイルの `reviews` を、保存のたびに消す: 元に戻せない。
- 見返しの上に、稼働とは別の「プロジェクト別」の表を足す: 稼働の表と、プロジェクトの行が二重になる。

## 確かめること
- 単体テスト: `rangeTasks`（日・週・月の範囲で、組と対象が規則どおり。`weekTasks` の既存のテストが、そのまま通る）。`projectProgress`。稼働の画面: 期間ごとに、タスクの表の範囲が変わる。プロジェクト別の表に完了・進捗が出る（0 件は `—`、未設定の行）。タスクの表にプロジェクトの列。見返しの見出し・気づきの欄が無い。`reviews` が `splitData`／`mergeData` で保たれる。ID が出ない。
- Playwright（Chromium）で、デモデータ: 日・週・月の切り替え・←→。確かめていない画面は「未確認」と書く。
