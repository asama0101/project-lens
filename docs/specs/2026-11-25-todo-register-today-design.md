# ToDo タブで、今日のタスクを登録する（仕事 4）

## 目的と理由
ToDo タブで、今日の ToDo を、その場で増やせるようにする。
- 今日の予定の枠が無い、突発のタスクを、ToDo タブから登録する（今は、「＋ 突発タスク」を押すと、スケジュール画面へ移る）。
- 「この週のタスク候補」のタスクを、今日へ入れる（今は、スケジュール画面で、枠を置く）。

今日の ToDo は、「今日の日付に予定の枠か実績があるタスク」（`todayTasks`）。したがって、「今日へ入れる」は、今日の予定の枠を足す操作になる。

## ゴール / 非ゴール / アンチゴール
- ゴール:
  1. ToDo タブの左の列で、突発タスクを登録できる（画面を移らない）。
  2. 候補の行の「今日へ」で、開始と長さを決めて、今日の予定の枠を足せる。
  3. 候補の行を、左の「今日の ToDo」へドラッグして離すと、同じ入力欄が開く。
  4. `npm test` が通る。
- 非ゴール: 時刻を決めない「今日やる」印（新しいデータは持たない）。左の列からの、枠の移動・削除（スケジュール画面で行う）。完了済みタスクを今日へ入れること。
- アンチゴール: 稼働・集計の数字が変わる（枠を足す操作は、スケジュール画面と同じ規則）。データ形式が変わる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- データ形式は変えない。画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープ。用語は「タスク」。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も直す。

## 案の比較（今日の枠の時刻の決め方）
| 案 | 内容 | 判断 |
|---|---|---|
| 1（採用。利用者が選んだ） | 「今日へ」で入力欄（開始・長さ）を開く。初期値は、今から 15 分刻みに切り上げた時刻から 60 分 | 時刻を自分で決められる。新しいデータが要らない |

## 決めたこと

### 突発タスク（ToDo タブ）
- 左の列「今日の ToDo」の見出しの横に、「＋ 突発タスク」を置く。ヘッダーの「＋ 突発タスク」も、ToDo タブにいるときは、画面を移らず、同じ入力欄を、左の列の上に開く（スケジュール画面など、ほかの画面にいるときは、今までどおり、スケジュール画面へ移る）。
- 入力欄は、スケジュール画面の突発タスクの入力欄（`urgentForm`）と同じ部品・同じ項目（件名・プロジェクト・長さ・日付・開始）・同じ規則（`addUrgentTask`）。日付の初期値は今日。状態は `S.urgentDraft` を使う。
- 登録に成功したら、入力欄を閉じ、ToDo タブにとどまり、左の列に、新しいタスクが出る（今日に枠があるため）。通知は、スケジュール画面と同じ文言。失敗したときは、通知だけで、入力欄と入力を残す。
- Escape キーで入力欄を閉じる（ToDo タブでも）。

### 今日へ入れる
- 対象: 「この週のタスク候補」の行のうち、未完了（Done・Cancelled 以外）のもの。完了した行には出さない。同じタスクが、すでに今日に枠を持っていても、入れられる（枠が増える）。
- 行に「今日へ」（`data-tdplan="<タスクの id>"`）。押すと、その行の下に、入力欄を開く: 開始（15 分刻み。初期値は、今から 15 分刻みに切り上げた時刻。最大 23:45）、長さ（15・30・45・60 分。初期値 60）、「今日に入れる」「キャンセル」。同時に開けるのは 1 行（完了の入力欄とは別の状態。両方開いたままにしない: 一方を開くと、もう一方を閉じる）。
- 「今日に入れる」: `addSession`（`core/sessions.js`。休みの日・枠の重なり・23:59 を超える長さは、スケジュール画面と同じ規則でエラー）で、今日の予定の枠を足す。会議との重なりは、警告（`warning`）を通知に添える。成功したら、入力欄を閉じ、通知「『件名』を今日の HH:MM–HH:MM に入れました」。左の列に、そのタスクが出る。失敗は通知だけで、入力欄と入力を残す。
- 状態は、メモリ上の `S.tdPlan`（`{ key: タスクの id, start, minutes }`）。画面の移動・週の移動・キャンセル・保存で外す。`render()` の検証で、タスクが無くなっていたら外す。
- ドラッグ＆ドロップ: 候補の行（未完了のもの）を `draggable` にし、左の列（`.tdtoday`）へ離すと、「今日へ」を押したのと同じ処理（その行の下に入力欄を開く）。離す先の列は、ドラッグ中、強調する。ドラッグの開始・終了で、既存のスケジュール画面のドラッグ（`data-dragtask`）と干渉しない（別の属性 `data-tdrag="<タスクの id>"`）。

### 文言・見た目
- 入力欄は、今の完了の入力欄・突発タスクの入力欄の、見た目の流儀に合わせる。狭い幅でも横にあふれない。暗い配色で読める（既存の変数）。

## 作る側に任せること
- 入力欄の細かい見た目・並び。ドラッグ中の強調の見た目。`S.tdPlan` の、初期値を作る関数の置き場所と名前（`urgentDefaultStart` を使う）。

## 確かめること
- 単体テスト: 突発タスクの入力欄が ToDo タブに出る・ヘッダーのボタンが ToDo タブで画面を移らない。「今日へ」の入力欄の初期値・成功で今日の枠が増える・重なり/休みのエラーで入力が残る・完了済みの行に出ない。ドラッグ＆ドロップの結線。
- Playwright（Chromium）で、デモデータを使って 1 回ずつ。確かめていない画面は「未確認」と書く。
