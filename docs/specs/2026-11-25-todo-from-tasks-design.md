# ToDo タブを、プロジェクトのタスクを元に作り直す（仕事 2）

## 目的と理由
ToDo タブを、個人の ToDo の入れ物から、プロジェクトのタスクを元にした「今週の見方」に作り直す。週の終わりに、タスクごとの使った時間と進捗を見返して、次の週のやり方を変える材料にする（改善活動）。

理由:
- 今の ToDo は、プロジェクトのタスクとは別のデータで、手で入れる。タスクの期限・予定の枠・実績と、二重管理になる。
- 「今週やるもの」は、タスクの期限と予定の枠から決まる。手で登録する必要がない。
- 「ToDo・タスク・件名」の言い方が、入り乱れている。

土台は、仕事 1（予定と実績を 1 つの作業枠に持たせる）。完了の入力欄は、その「実績を保存」を使う。

## ゴール / 非ゴール / アンチゴール
- ゴール:
  - 表示中の週のタスクが、自動で一覧に出る。
  - 完了を押すと、実績・状態・チェックリストを、1 つの入力欄でまとめて直して保存できる。
  - 週の見返し（タスクごとの時間・進捗・気づき）が出る。
  - 今日の優先に、前のタスク待ちのタスクも出る。
  - `npm test` が通る。
- 非ゴール:
  - 個人の ToDo（自由な件名の ToDo）を持つこと。
  - 手で一覧に足す操作（前倒し）。
  - 「回す」と、回した回数（要件から外した）。
  - 日ごとの画面（週の一覧だけ。今日の予定は、スケジュール画面と今日のタスクが持つ）。
- アンチゴール:
  - 共有ファイル（`data.json`）の、タスクの期限・状態を、勝手に変える。完了の入力欄で、利用者が保存したときだけ変わる。
  - 完了の保存が、途中までしか通らない（実績だけ保存されて状態が変わらない、など）。
  - 今の個人ファイルが、読めなくなる（`todos` が残っていても、読めて、無視される）。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- データ形式の正本は、`data/sample.json` と `src/core/schema.js`。形を変えたら、両方を直す。
- 「旧形式の移行・読み替えは持たない」。ただし、個人ファイルに `todos` が残っていても、エラーにせず、読み込むときに捨てる（下の「消すもの」）。
- 画面に ID を出さない。文言は日本語。`esc()` で必ずエスケープする。
- 用語は「タスク」にそろえる（画面・文書・コードのコメント）。「ToDo」は、タブの名前に残す。「件名」は、入力欄のラベルのときだけ使う。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も、同じ作業で直す。

## 案の比較
| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| 1（採用） | 週のタスクを、保存せず、タスクと枠から、その場で計算する純関数（`weekTasks`）にする | 二重管理がない。期限や枠を直すと、一覧も変わる。個人ファイルに増えるのは、`reviews` だけ | 週に載るかどうかの規則を、正しく作る必要がある |
| 2 | 週ごとの一覧を、個人ファイルに保存する（スナップショット） | 週の終わりの状態を、あとから正確に見返せる | 期限や枠を直しても、一覧が変わらない。二重管理に戻る |

## 決めたこと

### 今週の一覧（`weekTasks`）
- 表示中の週（月曜〜日曜）について、次のどれかに当たるタスクを出す:
  1. 未完了（Done・Cancelled 以外）で、期限が週の終わり以前のもの（期限超過を含む）。
  2. その週に、予定の枠の日付、または実績の区間の日付があるもの。
  3. 週の中で完了したもの（`doneAt` が週の中）。
- 前のタスクが未完了のタスクも、同じ規則で出す。行に「前のタスク待ち」と添える。
- 並び: 期限超過 → 今日・今週に予定の枠があるもの → 今週の期限 → 完了。同じ組の中は、期限の昇順、同じなら ID。
- 過去の週: 同じ規則で計算する。ただし、1 は「その週の終わり時点で未完了」を、現在の状態で近似する（過去の完了日が週の外のものは、完了を出さない）。
- 行に出すもの: プロジェクト名・件名・状態・期限・チェックの進捗（M/N）・その週の予定の分と実績の分。
- 手で足す・外す操作は、持たない。

### 完了の入力欄
- 行の「完了」を押すと、その行に入力欄が開く（開けるのは同時に 1 行）。
  - 実績: 日付・開始・終了（省略できる。初期値は、その日のそのタスクの予定の枠の時刻。なければ空）。入れるときは、仕事 1 の「実績を保存」と同じ規則（開始が今より後は不可・実績の区間の重なりは不可）。
  - 状態: 初期値は Done。ほかの状態も選べる。
  - チェックリスト: 項目の一覧と、「残りをすべてチェック」のボタン。
- 「保存」で、実績・状態・チェックリストを、1 回で保存する。1 つでも検査に通らなければ、何も保存しない。失敗したときの入力は、メモリ上の下書きに残す。
- 実績を保存したとき、タスクの状態が To Do・Waiting なら In Progress にする自動変更は、状態の欄の選択を優先する（状態を選んで保存するので、自動変更は行わない）。
- Done・Cancelled にするときの、未来の予定の枠の解除（実績を持つ枠は対象外）は、今のまま。

### 週の見返し
- 「完了 X / Y 件」: Y は、その週の一覧のタスクの数、X は、そのうち完了のもの。
- 「予定 P 分に対して実績 A 分」: その週の一覧のタスクの、予定の枠の自身の時間と、実績の区間（その週の日付）の合計。
- 表: タスクごとに、進捗（M/N。チェックリストが無ければ「—」）・予定・実績。
- 気づき: 今のまま、欄を離れたとき（`change`）に、個人ファイルの `reviews`（週の月曜日 → 文）へ保存する。空にするとキーを消す。
- 見返しの回した回数の列は、持たない。

### 今日の優先
- `rankTasks` が、前のタスクが未完了のタスクを外している規則をやめ、含める。理由の表示に「前のタスク待ち」を足す。点数の付け方は、今のまま（前のタスク待ちかどうかで点数を変えない）。
- 今日の優先に出る数（ガント・リストは上位 4 件、スケジュール画面は全部）は、今のまま。

### 消すもの
- 個人ファイルの `todos`、ToDo の作業枠（`todo.sessions`）、ToDo の `ownerOf`・`allSessions` の扱い、`schema.js` の ToDo の検査、`split.js` の ToDo の振り分け。
- 個人ファイルに `todos` が残っていても、読み込むとき（`mergeData`）に捨てる。保存し直すと、消える。
- スケジュール画面の右の列の「今日の ToDo」。稼働の「プロジェクト未設定」の行のうち、ToDo の列。
- `core/todos.js` の ToDo の操作（`addTodo` など）と `views/todo.js` の今の中身。`mondayOf` と、見返しの計算は、タスク向けに作り直す。
- `sample.json` の `todos`。`reviews` は残す。
- 画面の状態 `S.tdAct`・`S.tdDraft`・`S.tdAskDel` は、新しい画面の状態（完了の入力欄の行・下書き）に置き換える。

## 作る側に任せること
- `weekTasks` の置き場所（`core/todos.js` を作り直すか、`core/week.js` にするか）と、関数の名前。
- 画面の見た目（組の見出しの出し方、行の並べ方、狭い幅での折り返し）。
- チェックリストの保存の関数（今のタスクのチェックの操作を使う）。

## 確かめること
- 単体テスト: `weekTasks`（期限超過・今週の期限・今週の枠・今週の完了・前のタスク待ち・Cancelled・過去の週）。完了の保存（実績・状態・チェックが、1 回で通る。1 つでも失敗したら、何も変わらない）。見返しの数（件数・分数が、一覧と合う）。`rankTasks` が、前のタスク待ちを含む。個人ファイルに `todos` が残っていても読める。
- 既存のテストのうち、ToDo を前提にするものを、消すか、新しい規則に直す。
- Playwright（Chromium）で、一覧の自動表示・前のタスク待ち・完了の入力欄（実績・状態・チェック）・見返し・気づきの保存・今日の優先に前のタスク待ちが出ること・週の移動を、1 回ずつ。確かめていない画面は「未確認」と書く。
