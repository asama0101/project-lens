# ToDo タブ（日・週の ToDo と、週の見返し）（仕事 2）

## 目的と理由
プロジェクトのタスクとは別に、自分の日・週の ToDo を管理するタブを足す。「その日・その週にやること」を書いて消し込み、週の終わりに、「使った時間」「進捗」「翌日・翌週へ回した回数」を見返して、次の週のやり方を変える材料にする。

理由は、参考にした記事の考え方（仕組みは 1 つずつ作る、動いたかは回数で判定する、止まったものは縮める・捨てる）を、改善活動につなげたいため。ToDo ごとの時間・進捗・回した回数が見えると、「毎週回している ToDo」「見積りが外れる ToDo」に気づける。記事そのものの機能（13 週の計画、使った日数の自動判定）は、この仕事に含めない。

土台は、仕事 1（`docs/specs/2026-11-24-actuals-input-design.md`）で作り直した、予定とは別の実績の枠。ToDo の「使った時間」は、実績の枠の合計で持つ。

## ゴール / 非ゴール / アンチゴール
- ゴール:
  - 「ToDo」タブで、日の ToDo と週の ToDo を、追加・題の編集・完了・削除できる。
  - 週の ToDo を、日に割り当てられる（「今日へ」）。
  - 翌日・翌週へ回せて、回した回数が数えられる。
  - 実績（開始・終了）を入れられ、予定は、スケジュール画面で枠を置いて持つ。
  - 週の見返しで、ToDo ごとの進捗・予定・実績・回した回数と、気づきの欄が見える。
  - `npm test` が通る。
- 非ゴール:
  - 13 週の計画、使った日数（5 日中何日か）の自動判定、「縮める」「捨てる」の提案。
  - 繰り返しの ToDo（毎週同じ ToDo を自動で作る）、複数人での共有、通知、開始・停止のタイマー。
  - ToDo を、ガントチャート・リスト・「今日の優先」に出すこと。
- アンチゴール:
  - 共有ファイル（`data.json`）に、ToDo の項目が入る。
  - 既存のタスク・作業枠・稼働の数字が変わる。
  - ToDo の実績の枠が、「孤立した枠」の警告になる。

## 制約
- Windows 専用、Node 24 以上。`src/` を変えたら `npm run build` して `assets/project-lens.html` をコミットする。
- ToDo は個人ファイル（`personal.json`）に置く。共有ファイルは変えない。形は、`src/core/schema.js`（検査）、`src/core/split.js`（分割・結合）、`data/sample.json` に反映する（正本）。
- 「旧形式の移行・読み替えは持たない」。ToDo の項目が無い既存の `personal.json` は、そのまま読める（`todos` が無ければ空）。
- 画面の文言は日本語。画面に ID（`T-0001`）は出さず、件名で言う。
- 変更の PR 本文に、「`development.md`: 直した節の名前」を書く。`README.md`・`docs/guide.md` の画面の説明も、同じ作業で直す。

## 案の比較
| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| 1（採用） | 個人ファイルに専用の `todos` を持つ。作業枠が、タスクと ToDo の両方を指せるようにする | スケジュールの枠・実績・稼働が、ToDo にもそのまま使える。共有ファイルは変わらない | 枠を読む箇所（約 10 か所）を、ToDo も含める形に直す |
| 2 | ToDo を、プロジェクトなしのタスク（`projectId: null`）として、タスクの配列に入れる | 枠の仕組みは、直さずに済む | タスクを読む箇所が 22 ファイルに約 120 あり、ToDo が、ガント・リスト・今日の優先に混ざる。共有ファイルに入る（個人のものと分ける方針に反する） |
| 3 | ToDo の時間を、ToDo の中に持ち、カレンダーの枠とは別にする | 枠を読む箇所を直さずに済む | スケジュール画面で、ToDo の時間を確保できない（枠の確保は、スケジュール画面で行う） |

画面の並べ方は、案 A（左に「この週」、右に「今日」の 2 列）を、利用者が選んだ（sidekick プラグインの返答として届いた）。案 B（1 列で週・日を切り替える）は、採らない。

## 決めたこと

### データ（個人ファイル `personal.json`）
- `todos`: 配列。1 件は次の形（私の判断を含む）。
  - `id`: `T-0001`（`T-` + 4 桁。ToDo の中で、最大番号 + 1）
  - `scope`: `"week"` か `"day"`
  - `title`: 件名（空にできない）
  - `date`: `YYYY-MM-DD`。`week` は、その週の月曜日の日付。`day` は、その日の日付。
  - `parentId`: 任意。`day` の ToDo だけが持てる。値は、`scope: "week"` の ToDo の `id`（週の ToDo を、その日に割り当てた分）。
  - `doneAt`: 完了した日（`YYYY-MM-DD`）か `null`
  - `checklist`: 任意。今のタスクと同じ形（`[{ id, text, done }]`）。進捗は「済み / 全体」で表す。
  - `carried`: 回した回数（0 以上の整数。初期値 0）
- `reviews`: 任意。`{ "<週の月曜日の日付>": "気づきの文字列" }`。
- 作業枠（`sessions`）は、今までどおり個人ファイルの平らな配列で、`taskId` に ToDo の `id` を入れてよい。結合（`mergeData`）は、`taskId` が共有のタスクならタスクへ、`todos` の ToDo ならその ToDo の `sessions` へ戻し、どちらでもなければ孤立した枠にする（今と同じ）。
- 検証（`validate`）: `scope`・`date`・`parentId`（存在する週の ToDo か）・`doneAt`・`carried`・`checklist` の形、ToDo の `id` の重複、ToDo の枠の検査（今のタスクの枠と同じ。重なりは、同じ種別どうしで、タスクをまたいで判定する）。

### 画面（「ToDo」タブ。スケジュールと稼働の間）
- 2 列（案 A）。上に、週の移動（← → 今日）。
  - 左: 「この週の ToDo」。週の ToDo（`scope: "week"`、その週の月曜日の `date`）だけを出す（日の ToDo は、左には出さない）。
  - 右: 「表示中の日」の ToDo（`scope: "day"` で、その日の `date`。週の ToDo から割り当てた分も、単独の日の ToDo も含む）。右の見出しに、日付と「‹ 前の日」「次の日 ›」「今日」を置く。週を移動したとき、右の日は、その週に今日が含まれれば今日、含まれなければその週の月曜日になる。
- 各行に、完了のチェック、件名、進捗（チェックリストがあるとき「M/N」）、予定（分）、実績（分）。回した回数が 1 以上なら「N 回回しています」を添える。
- 行の操作: 完了のチェック、題の編集、削除、チェックリストの項目の追加・チェック・削除、「実績を入れる」、回す（日: 「明日へ回す」、週: 「来週へ回す」）、週の ToDo の「この日へ」（右が今日のときの文言は「今日へ」）。
- 追加: 左の末尾に「＋ 週の ToDo を追加」、右の末尾に「＋ 日の ToDo を追加」（件名を入れて Enter。日本語入力の変換確定の Enter では確定しない）。
- 狭い画面では、2 列が縦に並ぶ。
- 週の見返し（下の「見返し」）を、2 列の下に出す。

### 操作の規則（私の判断を含む）
- 「この日へ」: 週の ToDo から、右の列の日（過去・未来の日でもよい）の日の ToDo（`parentId` つき、件名は同じ）を作る。同じ週の ToDo の同じ日の分が、すでにあるときは何もせず、通知で知らせる。
- 回す:
  - 日の ToDo → 次の営業日（`core/holidays.js` の `offDayChecker` で、休みでない最初の日）へ `date` を動かし、`carried` を 1 増やす。
  - 週の ToDo → `date` を 7 日後（来週の月曜日）へ動かし、`carried` を 1 増やす。この ToDo に割り当てた日の ToDo は、そのまま（その日の分として残る）。
  - 完了した ToDo は、回せない。
- 完了: チェックで、今日の日付を `doneAt` に書く。外すと `null`。週の ToDo の完了は、割り当てた日の ToDo の完了とは独立。
- 削除: ToDo と、その実績・予定の枠を消す。週の ToDo を消すと、割り当てた日の ToDo の `parentId` を外す（日の ToDo は、単独の日の ToDo として残る）。
- 時間:
  - 予定の時間は、スケジュール画面で置いた予定の枠の合計。実績の時間は、実績の枠の合計。
  - 週の ToDo の時間は、自分の枠と、割り当てた日の ToDo の枠の合計。
  - 「実績を入れる」: 開始・終了の欄（日付の初期値は、右の列の日。時刻の初期値は、その日の予定の枠があればその時刻、なければ今を 15 分刻みに切り捨てた時刻から 60 分）。仕事 1 の `addActual` の規則（開始が今より後は不可、実績どうしの重なりは不可）に従う。状態（In Progress）の自動変更は、ToDo にはない。
  - 予定の枠は、スケジュール画面の右の列に出す「今日の ToDo」を、カレンダーへドラッグして置く（今の「今日のタスク」と同じ操作）。置いた枠は、予定（`planned`）。
- ToDo の枠は、スケジュール画面のカレンダーに、件名だけで出る（プロジェクト・状態の文字は出さない）。選んで、実績の入力欄（仕事 1）から実績を入れられる。
- 稼働: ToDo の実績の枠は、「プロジェクト未設定」の行のタスクの列に入る（プロジェクトのない実績の枠と同じ。今の規則）。

### 見返し（ToDo タブの下。表示中の週）
- 見出しの数: 「完了 X / Y 件」。Y は、`date` がその週に入る、週の ToDo と、`parentId` を持たない日の ToDo（週の ToDo から割り当てた日の ToDo は、数えない。同じ作業の重複になるため）。X は、Y のうち `doneAt` が入っているもの（完了した日が、その週の外でもよい）。したがって X は Y を超えない。回した ToDo は、`date` が動くので、回した先の週の件になる。完了を外すと、X から外れる。
- 「予定 P 分に対して実績 A 分」: 上の件の、日付がその週（月曜〜日曜）に入る枠の合計。週の ToDo は、割り当てた日の ToDo の、その週の枠を含む。回した ToDo の、回す前の週にある枠は、その週の数に残る（作業をした日の週で数える）。
- 表: ToDo ごとに、進捗（M/N。チェックリストがなければ「—」）、予定、実績、回した回数。回した回数が 1 以上の行は、強調する。
- 「気づき」: 自由に書く欄。入力が済んだとき（欄を離れたとき）に、`reviews` へ保存する。
- 見返しは、金曜に限らず、いつでも出す。

### 細部の判断（すべて私の判断。実装者の確認で出た質問への答え）
- ToDo の予定の枠も、仕事 1 の規則のまま「未確認」になる（過ぎていて、重なる実績が無い）。札・橙の点線・稼働画面の「未確認 N 件」に、ToDo の枠も数える。判定の関数（`sessionKind`）は、タスクと ToDo で分けない。
- 回すと、その ToDo の、回す前の日にある予定の枠のうち、重なる実績の枠が無いものを消す（回したので、その日の予定は意味がなくなる。未確認が残らないため）。実績の枠は消さない。週の ToDo を回しても、割り当てた日の ToDo の枠は、そのまま。
- ToDo を完了にしても、その ToDo の未来の予定の枠は、そのまま残す（利用者が、スケジュール画面で消す）。
- スケジュール画面の右の列の「今日の ToDo」は、今日の日の ToDo（`scope: "day"`、`date` が今日。完了したものは薄く、末尾に出す）。週の ToDo は、枠を置けない（先に「この日へ」で日の ToDo にする）。ドラッグでは、ToDo の `date` と違う日にも、予定の枠を置ける（枠の日付は、ToDo の `date` と独立）。
- ToDo タブの右の列でも、完了した日の ToDo は、薄くして、末尾に残す（今日のタスクと同じ）。
- 週の ToDo の件名を直すと、割り当てた日の ToDo のうち、直す前の件名と同じ件名のものも、新しい件名にする。日の ToDo の件名だけを直したときは、その ToDo だけが変わる。

## 作る側に任せること
- ToDo の枠を読む箇所の直し方（`allSessions`・稼働・`dnd`・`prio` など、枠をタスクの `sessions` から読んでいる約 10 か所を、ToDo の枠も含む形に直す方法。枠の持ち主を引く小さな関数を足すなど）。
- 行の見た目（予定・実績・回した回数の並べ方）、狭い画面の列の幅、気づきの欄の大きさ。
- チェックリストの編集の画面（今のタスクの編集の窓と同じ部品を使えるなら使う）。
- ToDo の `id` の採番の細部（`nextTaskId` に倣う。変更履歴は持たない）。
- 週の見返しの表で、日の ToDo の行の並び順。

## 確かめること
- 単体テスト: ToDo の追加・題の編集・完了・削除、「今日へ」（同じ日の重複は作らない）、回す（日: 次の営業日。休みの日をまたぐ。週: 7 日後。`carried` が増える。完了は回せない）、削除で `parentId` が外れる、ToDo の枠の結合・分割（`mergeData` が ToDo の `sessions` へ戻す。孤立した枠にならない）、`validate`（形の不正、`parentId` の不整合）、時間の合計（週の ToDo は、割り当てた日の分を含む）、見返しの数（割り当てた日の ToDo を数えない）、稼働（ToDo の実績が「プロジェクト未設定」に入る）、描画（2 列、回した回数の表示、ID を出さない）。
- 既存のテストが、そのまま通る（既存のタスク・枠・稼働の数字が変わらない）。
- Playwright（Chromium）で、追加 → 「今日へ」→ 実績を入れる → 回す → 見返しの数、スケジュール画面で ToDo を置く・実績を入れる、を 1 回ずつ実行する。確かめていない画面は「未確認」と書く。
