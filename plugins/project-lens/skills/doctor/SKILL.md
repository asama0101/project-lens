# doctor: 動く環境かを診断する

project-lens が動く環境かを診断し、足りないものと、その対処の手順を伝える。診断だけで、何も変更しない。祝日一覧（内閣府）への接続は試すが、こちらのデータは何も送らない。別の PC で使い始めるときや、動かないときに使う。

## 用語
| 用語 | 意味 |
|---|---|
| `[OK]` | 問題のない項目 |
| `[NG]` | 必須の項目の不足。動かないので、対処が要る |
| `[任意]` | 使う機能のときだけ必要な項目 |
| `[情報]` | プラグインのバージョンの情報 |
| 「→」 | 出力の中で、対処の手順を示す印 |

## 全体の流れ
| 手順 | やること | 終わりの目印 |
|---|---|---|
| 1 | 診断のコマンドを実行する | 出力を読んだ |
| 2 | 結果を項目ごとに伝える | 全項目を伝えた |
| 3 | 対処のコマンドは、頼まれたときだけ実行する | 頼まれた分だけ実行した |
| 4 | 対処のあと、もう一度診断する | `[NG]` が無くなった |

## 手順

### 手順1: 診断を実行する
目的: 環境の状態を、`[OK]`・`[NG]`・`[任意]`・`[情報]` で出力させる。

次のコマンドは、環境を診断して結果を出力する（何も書かない）。終了コード 3 は「必須の項目に [NG] がある」で、失敗ではない。出力をそのまま読む。

```
node "${CLAUDE_PLUGIN_ROOT}/tools/doctor.js" --data "${CLAUDE_PLUGIN_DATA}"
```

起動コマンド `node` が見つからないとき、または構文エラーで起動に失敗するときは、Node.js 24 以上が入っていない。`winget install OpenJS.NodeJS.LTS` を案内し、ターミナルを開き直してからもう一度実行してもらう。

### 手順2: 結果を伝える
目的: 項目ごとに、利用者が次に何をすればよいかを伝える。
- `[OK]`: 一言で済ませる。
- `[NG]`: 必須の項目。動かないので、「→」の対処を番号つきの手順で、コマンドをそのまま写して伝える。
- `[任意]`: 使う機能のときだけ必要。どの機能で要るかは、項目名で分かる（祝日一覧への接続は祝日の取得、Excel の読み取りは Excel の取り込み、予定表の MCP の指定は予定表の取り込み）。その機能を使うかを聞き、使うなら「→」の手順を伝える。使わないなら、触れずに終える。
- `[情報]`: プラグインのバージョン。今の版を伝える。「GitHub に vX.Y.Z があります」と出ているときは、「→」の手順（更新と開き直し）を伝える（実行は頼まれてから）。確認できなかったときは、その理由を一言で伝える。

### 手順3: 対処を実行する
目的: 環境を変える対処を、頼まれたときだけ実行する。

対処のコマンドは、利用者が頼むまで実行しない。`winget`・`ensurepip`・`setup --yes` は、環境を変えるため。実行を頼まれたら、1 つずつ実行して結果を伝える。

`xlsx.js setup` は、`--yes` なしの出力（入れ先と内容）を見せて、入れ先（専用の venv が推奨。システムは版の衝突に注意）を選んで承認を得てから、`--yes`（システムに入れるときは `--system --yes`）を付けて実行する。

### 手順4: もう一度診断する
目的: 対処で `[NG]` が無くなったことを確かめる。

対処のあとは、手順の最後の「もう一度 doctor を実行する」のとおり、この `/project-lens:doctor` をもう一度実行して、`[NG]` が無くなったことを確かめる。
