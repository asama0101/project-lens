# mcp: 予定表の MCP を指定する

予定表の取り込み（`/project-lens:intake calendar`）で使う MCP の指定を、管理する。接続中の MCP から候補を提案し、承認後に保存して、1 件取得して動作を確かめる。MCP 自体は利用者が Claude Code に用意したものを使い、このプラグインには同梱しない。指定は `${CLAUDE_PLUGIN_DATA}` の `project-lens-mcp.json` に保存し、プロジェクトの `data.json` には入れない。

引数: $ARGUMENTS

起動コマンド `node` が見つからないとき、または構文エラーで起動に失敗するときは、Node.js 24 以上が入っていない。`winget install OpenJS.NodeJS.LTS` を案内し、ターミナルを開き直してからもう一度実行してもらう。

## 用語
| 用語 | 意味 |
|---|---|
| MCP | Claude Code に接続した、外部のツールの提供元。予定表の MCP は、予定を取得するツールを持つ |
| `server`・`listTool` | 保存する指定の項目。`server` は MCP のサーバー名、`listTool` は期間を指定して予定を取得するツールの名前 |
| `selfEmails`・`selfNames` | 自分のメールアドレスと名前。取り込みで、自分だけ・自分と会議室だけの予定（作業ブロックなど）を会議として取り込まないために使う |
| `roomKeywords` | 会議室の名前に含まれる言葉。会議室を見分けるために使う |
| `resource` | MCP が、会議室・備品の参加者に付ける種別 |

## 全体の流れ
| 手順 | やること | 終わりの目印 |
|---|---|---|
| 1 | 現状の指定を表示する | 結果を伝えた（`show` ならここで終わる） |
| 2 | 接続中の MCP から候補を提案する | `server` と `listTool` の候補を示した |
| 3 | 承認を得て、`server` と `listTool` を保存する | 保存した |
| 4 | 自分のメールアドレス・名前と会議室の言葉を聞いて保存する | 保存した（または保存済みで聞かなかった） |
| 5 | 試しに取得して確認する | 取得できた件数と参加者の表示を確かめた |

## 手順

### 手順1: 現状を表示する
目的: 予定表用の指定が、すでにあるかを確かめる。

次のコマンドは、予定表用の指定の有無と内容を読んで表示する（何も書かない）。結果を伝える。引数が `show` のときは、ここまでで終わる。それ以外（空・`calendar`）は、手順2 へ進む。予定表の指定がすでにあるときは、変えるかを聞き、変えないなら手順4 へ進む。

```
node "${CLAUDE_PLUGIN_ROOT}/tools/mcpconf.js" --data "${CLAUDE_PLUGIN_DATA}" show
```

### 手順2: 候補を提案する
目的: 予定表を取得できる MCP のツールを、利用者に示す。

予定表（`calendar`）について、いま接続している MCP のツール一覧から候補を選ぶ。**サーバー名とツール名を明示して**示す。
- `server`、`listTool`（期間を指定して予定を取得するツール）
- 該当するツールが見つからないときは、見つからなかったと伝え、MCP の用意（`claude mcp add` など）を案内して終わる。推測で指定しない。

### 手順3: 承認を得て保存する
目的: 承認された `server` と `listTool` を保存する。

次のコマンドは、承認された内容を `project-lens-mcp.json` に書く。

```
node "${CLAUDE_PLUGIN_ROOT}/tools/mcpconf.js" --data "${CLAUDE_PLUGIN_DATA}" set calendar server=<サーバー名> listTool=<ツール名>
```

### 手順4: 自分のメールアドレス・名前と会議室の名前を聞いて保存する
目的: 取り込みで、自分だけ・自分と会議室だけの予定（作業ブロックなど）を会議として取り込まないようにする。自分のメールアドレスも名前も未設定のときは、何も除外されない。

1. 手順1 の表示で `selfEmails` か `selfNames` が保存済みなら、聞かずに保存済みの値を伝えて、手順5 へ進む（変えたいと言われたときだけ聞き直す）。
2. `selfEmails` だけが保存済みで `selfNames` がないときは、値を伝えるときに、「予定表がメールアドレスを表示名に置き換えて返す場合は、名前も保存できる」と一言添える。
3. 次の 3 つを聞く。どれも答えは任意で、答えがなければ保存しない。
   - 自分のメールアドレス（複数可。予定表の参加者に載る形。例: 会社と個人のアドレス）。
   - 自分の名前（複数可。予定表が、メールアドレスを表示名に置き換えて返すときのため）。予定表の参加者に載る形のとおりに、そのまま入れる。前後の空白と大文字小文字だけを区別しない完全一致。
     - 同じ表示名の別人がいると、その人を自分とみなして本物の会議を取り込まなくなる。同じ表示名の人に心当たりがないか、利用者に確かめる。ある場合は、その名前を入れず、メールアドレスだけにする。
     - カンマ（,）を含む表示名（例: 「Yamada, Taro」）は、保存の区切りと同じなので、保存できない。その名前も入れず、メールアドレスだけにする。
   - 会議室の名前に含まれる言葉（複数可）。MCP が会議室を `resource` 種別で返すときは不要。何も保存しないときは「会議室」が使われる。
4. 次のコマンドは、聞いた内容を `project-lens-mcp.json` に書く。**答えのあった項目だけをコマンドに入れる。答えのなかった項目は書かない**（書かなかった項目は、保存済みの値のまま残る）。次の形は 3 項目すべてを書いた例。
   ```
   node "${CLAUDE_PLUGIN_ROOT}/tools/mcpconf.js" --data "${CLAUDE_PLUGIN_DATA}" set calendar selfEmails="<メール,メール>" selfNames="<名前,名前>" roomKeywords="<言葉,言葉>"
   ```
5. 値は、必ず二重引用符で囲む（表示名に空白があると、引数が分かれて失敗するため。例: `selfNames="Taro Yamada,山田 太郎"`）。値に二重引用符・`$`・バッククォート・改行があるときは、保存しない（シェルが解釈するため）。
6. 保存済みの `server`・`listTool` は、そのまま残る。項目を空（`selfEmails=`）にすると、その項目を消す。消したいときだけ、空で渡す。

### 手順5: 試しに取得して確認する
目的: 指定したツールで予定が取得できること、自分の名前が取得結果と合うことを確かめる。

今日の予定を、指定したツールで取得する。
1. 使った MCP のサーバー名とツール名を添えて、取得できた件数と 1 件の件名を見せる。
2. 参加者（メールアドレス・表示名・人か会議室か）が取得できるかも伝える（取得できないと、自分だけの予定を除外できない）。
3. `selfNames` が保存済み（今回保存した場合を含む）のときは、取得できた参加者の表示名を見せ、保存した名前と同じもの（前後の空白と大文字小文字を除いて同じ）があるかを、利用者に確かめてもらう。完全一致でないと、警告なしで除外されないため。
4. 同じものがない、または今日の予定に自分が載っておらず確かめられないときは、その旨を伝え、手順4 に戻って名前を入れ直すかを聞く。入れ直すときは、手順4 の「保存済みなら、聞かずに」にかかわらず、名前を聞き直す。
5. 取得に失敗したら、理由を伝え、指定を残すか消す（`clear calendar`）かを聞く。

終わったら、`/project-lens:intake calendar` で取り込めることを伝える。
